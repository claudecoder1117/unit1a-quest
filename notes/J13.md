## 1. What was built

### 1.1 `qa/job-walk.mjs` — four acceptance criteria, each MEASURED

```sh
node qa/job-walk.mjs               # all: cold · three jobs × two viewports · S9
node qa/job-walk.mjs cold          # the pinned path + the two-pass board
node qa/job-walk.mjs jobs          # three jobs at 375×667 dark and 1280×800 light
node qa/job-walk.mjs s9            # COMPOSED S9's ten criteria, re-scored
node qa/job-walk.mjs gate          # the fast subset tests/job-coldopen.test.mjs spawns
  --engines chromium,webkit  --one  --trace  --keep  --lag 700  --at 19:30  --out <dir>
```

Four devices make the numbers honest rather than flattering:

1. **The clock is moved by a CONSTANT offset onto tonight at 19:30** (`--at`). A board is a function
   of the hour — after 22:00 none posts, and Mon–Fri 07:00–14:15 posts the RUN shape only (G5) — so a
   QA that only runs after dinner is not a QA. Because the offset is constant, every wall-clock delta
   the app measures and every delta this file measures is untouched. Between jobs the walk adds whole
   days (`window.__clockShift`), because a student who walks out of tonight's job does not get a
   second board at 19:31.
2. **`page.js` and `plan.js` are served with a deliberate 700 ms lag** (`--lag`). On a loopback server
   every module lands in ~20 ms, which makes "the board paints before `page.js` arrives" untestable —
   and that ordering *is* what two passes means. The lag is the cheapest honest stand-in for a link
   that is not loopback, it applies to those two files only, and **the 20 s cold-open budget is
   measured with it on**, so the headline number is pessimistic.
3. **The geometry is sampled on every animation frame**, from before the first paint until pass 2
   lands, and the board's boxes are measured **relative to the panel's own top-left**. Home repaints
   itself twice on its own (`renderLight` → `render`), so an absolute rect conflates the hero moving
   with the board's two passes; subtracting the panel origin is what makes the criterion mean what it
   says. The absolute rects and the browser's own Layout Instability score are reported beside it.
4. **Every screenshot carries its own probability audit.** At each shot the page re-imports
   `guard.js`, `call.js` and `econ.js`, recomputes each printed number from the live save, and diffs
   it against the rendered text: the guard bars (`guardBars(dist)`, and that they sum to 100), the
   cold-start line (`uniform 1/N` against the bars actually drawn), the four call rungs
   (`callsFor(guard.rankOf(save))`), the envelope's evidence line (`qHatDetail`), the vault's
   break-even q, and a scan of the sealed envelope for `EV-max` / `argmax` (Global law 6).

`jobs` and `s9` also patch `/js/widgets/index.js` in memory the way `qa/s9-walk.mjs` does, so the
driver can answer a tap-to-build notation widget or a pairs grid correctly instead of typing `1` at
it. **The cold-open measurement is served the shipped bytes, unpatched** — the patch is switched off
for it.

## 2. Exported API — exact signatures

Neither file exports anything: `tests/job-coldopen.test.mjs` is a `node:test` suite and
`qa/job-walk.mjs` is a CLI. Their contract is the CLI and its exit code:

```
node qa/job-walk.mjs [cold|jobs|s9|gate|all] [flags]      exit 0 = every criterion measured green
  --engines <list>   chromium (default), webkit, or both, comma-separated
  --one              only the 375×667 dark pass of `jobs`
  --lag <ms>         delay on /js/page.js and /js/plan.js only (default 700)
  --at HH:MM         the local evening the page's clock is pinned to (default 19:30)
  --out <dir>        where the PNGs and report-<mode>.json go (default qa/screenshots/job-walk)
  --trace            one line per beat        --keep   leave the browser open on a failure
```

`qa/screenshots/job-walk/report-<mode>.json` is the machine-readable record:
`{ rows[], fails[], known[], warns[], shots[], s9[], probs: { checked, bad[] } }`.
`tests/job-coldopen.test.mjs` reads `report-gate.json`'s `known[]`.

**The known-open register.** `qa/job-walk.mjs` carries a `KNOWN` array — the same device
`qa/audit-allow.json` gives the layout auditor. A failure whose text matches a `KNOWN` entry is
printed loudly under **KNOWN OPEN**, with its owner and its one-line fix, and does **not** set the
exit code; anything else fails the run. A test then asserts the register holds **exactly** the two
ids below, so a new regression cannot hide behind it.

## 5. What a harsh critic says about the screenshots

Everything here is a defect I would file if I had not built the harness. None of it is in a file J13
owns, so all of it is a Request or an Open issue; each one names its own measurement.

**1. The board the student reads on Home is not the board the job charges him.**
`cold-chromium-1-home.png` prints `A … posted 173 · B 171 · C 216 · D 216 · E 187`. One tap later
(`cold-chromium-2-guard.png`) the same five contracts read **189 / 202 / 247 / 231 / 187**. Cause,
isolated by re-running `postBoard` both ways in the page: `home.js fillBoard` calls
`postBoard(save, today, {…compose, now, page})` with **no `tellFor` hook**, while
`screens/job.js:203` passes `tellFor: tellHookFor(save)`. Home prints the no-tell posted; the job
screen re-prices with the live tells. This contradicts G1's Global law 4 ("the board is a projection
of the save — nothing the board posts is a second source of truth") and G9 #4 ("a reviewer can
recompute any number on any screen"). Request 2. Register id `home-board-no-tell`.

**2. Pass 1 is 90 % dots, and the 10 % that is ink is wrong.**
G7 enumerates what pass 1 carries: "contract labels, lock counts, cold days, wing labels, `~N min`,
the end time, the projected split, per-wing supply — all derivable from `save.cards` and `dueList`".
Measured: `label:placeholder locks:placeholder cold:placeholder posted:placeholder wing:placeholder
supply:placeholder`. **Only `posted` is supposed to wait for pass 2; all six wait.**
`cold-chromium-0-pass1.png` is five rows of `A · · · · · · · · locks · · d cold · posted · · · ·`
with an orphaned `—` under each. Worse, the one real line is rewritten:
`JOB · ~13 min · ends 19:42 · ~43 % game` → `JOB · ~20 min · ends 19:49 · ~27 % game`. The first
thing Home tells the student about tonight is wrong by **7 minutes and 16 points of split**. The
geometry is frozen (good) but the *content* is not what G7 promises.

**3. On a 375 px phone, every decision in the job is below the fold.** Measured, not eyeballed:

| the decision | where it sits | screen |
|---|---|---|
| the primary button that starts the job | y **1188–1253** | 667 px |

| the payout beat (payout line, chain ticks, BAG / PUSH) | y **863** | 667 px |

The keyboard path is complete (`Enter`, `1–4`, `B`, `K`, `W` all work, and the call row is

**4. At ≥ 1024 px the job screen has no right rail.** G6: "≥ 1024 px: the board lives in the 320 px

## 6. Deviations from COMPOSED-GAME.md

1. **The two failing criteria are shipped as `node:test` `todo`s, not deleted or softened.** J13's
   acceptance says "zero layout shift between passes"; it is 47.69 px and the fix is in a file J13
   does not own (BUILD-POLICY §2). The house precedent is J9, which ships G3.7 proof 2 as a failing
   `todo` that prints its own counterexample. Both J13 `todo`s assert the criterion **as written**
   and print the measured number on every suite run, and a third (passing) test pins the known-open
   register to exactly those two ids so nothing else can hide in it. `node --test tests/` exits 0.
2. **"A COLD visit" is read as a cold BROWSER, not a first-ever save.** A brand-new save has no test
   date, so it posts no board and the pinned path does not exist on it (G5's `nodate` gate). The walk
   uses a mid-week save with **no `save.game`** — the student's first job ever — in a brand-new
   context with an empty HTTP cache and the service worker blocked. That is the pessimistic reading;
   a warm SW would only make the number smaller.
3. **The 700 ms lag on `page.js` / `plan.js` is mine, not the spec's.** Without it the two-pass
   ordering is unobservable on loopback (both modules land in ~20 ms, before the first sampled
   frame). It is applied to those two files only and the 20 s budget is measured with it on.
4. **`jobs` and `s9` patch `/js/widgets/index.js` in memory** (the recorder + `__force` override from
   `qa/s9-walk.mjs`) so the driver can answer every part type. **`cold` does not** — the number in
   §4.1 is measured against the shipped bytes.
5. **The page's clock is offset onto 19:30** so the evening JOB board posts regardless of when the
   QA runs. Constant offset, so no measured duration changes.
6. **S9 #3 is scored on `#/card/not-01` when the drawn target carries no notation.** The job mounts
   `card.js` unchanged, so #3 is the study layer's property; the walk cannot choose which card the
   composer deals. Both numbers are printed.
