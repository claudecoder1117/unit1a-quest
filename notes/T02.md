## Exported API

### `site/js/rng.js`
```js
cyrb53(str, seed = 0) → number            // 53-bit hash, [0, 2^53)
seed32(strOrNumber) → uint32              // cyrb53(str) >>> 0  (a number is truncated)
seedTag(strOrNumber) → 'a91f2c'           // 6 lowercase hex chars for display
mulberry32(seed) → Rng                    // seed: uint32 or string (hashed)
rngFrom(...parts) → Rng                   // mulberry32(cyrb53(parts.join('|')) >>> 0)
Rng = { seed, draws,
        next() → [0,1), int(lo, hi) → inclusive (int(hi) = [0,hi]; either order), float(lo=0, hi=1),
        chance(p) → bool, pick(arr) → el|undefined, weighted(arr, weights), shuffle(arr) → NEW array,
        sample(arr, k), fork(label) → Rng (depends on seed+label only, not on draws made) }
```

### `site/js/grader/normalize.js`
```js
normalizeText(raw, opts?) → string   // opts: {prefix:true, trailingDot:true, degrees:true, units:true, fractions:true, lower:true}
stripPrefix(s) → string              // just the leading `x =` / `m =` / `m∠ABC =` / `=` rule (per roots token)
parseNumber(raw, opts?) → {ok:true, value: Rat|number, kind:'rational'|'float', text, normalized}
                        | {ok:false, err, msg, normalized, vars?, pos?}
   // err ∈ 'empty'|'comma'|'sci'|'variable'|'syntax'|'char'|'equals'|'divzero'|'exponent'|'toolarge'|'toolong'

tolFor(part) → number                // part.tol ?? 0.01
DEFAULT_TOL = 0.01
isTooLong(raw) → bool                // raw.length > MAX_INPUT — check BEFORE normalizing
MAX_INPUT = 2000, MAX_TOKENS = 1000, MAX_DEPTH = 120   // parser caps; breaching one is err 'toolong'

// rationals {n, d}: d > 0, reduced, safe integers; every op throws ParseError('toolarge') instead of going inexact

// shared parser
tokenize(normalizedText) → Token[]         // {t:'num'|'var'|'op'|'lp'|'rp'|'eq'|'comma'|'end', v?, i}; throws ParseError('char')
parseExpr(tokensOrText) → Ast              // {t:'num'|'var'|'neg'|'pos'|'add'|'sub'|'mul'(implicit)|'div'|'pow'(k)}
evalAst(ast, algebra) → V                  // algebra = {num(text), variable(name), neg, add, sub, mul(a,b,implicit), div, pow(v,k)}
astVars(ast) → string[]
NUM                                        // the constant-expression algebra (Rat exact; touches a float → float)
class ParseError extends Error { code, pos?, got?, want?, vars? }
```
Grammar (superset of S3): `expr := term (('+'|'-') term)*; term := unary (('*'|'/'|IMPL) unary)*; unary := ('-'|'+') unary | pow; pow := atom ('^' INT)?; atom := NUM | VAR | '(' expr ')'`. IMPL only for NUM→VAR, NUM→`(`, `)`→`(`, `)`→VAR, VAR→`(` (so `nn`, `n2`, `(n+1)2`, `3 4` are syntax errors with targeted messages). `/` is a term-level operator (the algebra decides what may be divided: NUM anything, POLY constants only, RATFUN anything). `**` → `^`. Unary `+` accepted (`+30`).

Normalization order (matters): trim → dashes `− ‐ – — ｰ ⁻` → `-`, `× · ⋅ ∗` → `*`, `⁄` → `/`, `**` → `^`, superscripts → `^k`, `° º ˚ ∘` → `°` → vulgar fractions (`<int>½` → `(int+(1/2))`, bare/sign-prefixed `½` → `(1/2)`) → **NFKC** → lowercase → prefix strip → trailing `.` → `°` + `deg|degs|degree(s)` → units `units?|u|cm|mm|in|inch(es)` after a digit or `)` → `a b/c` mixed → whitespace collapse.

### How the `factored` grader (T03) maps onto this — the rule order, verified by `tests/poly.test.mjs`'s `classify`
1. `detectRootSet(raw).isRootSet` → `wrong` "this asks for the factored form, not the roots".
2. `=` handling: split on `=`, **drop a side only if it is 0 or the target *as typed*** (`factorStructure(side).topLevel === 'sum' || .typedBack`) — a correct factoring also *expands* to the target, so polynomial equality alone would drop the answer. Exactly one side must remain, else `malformed`.
3. `parsePoly(side, {var})` → `!ok` ⇒ `malformed` (free), message from `err`: `wrong-var` → "use the variable n" (`.want`), `equals`, `div-nonconst`, `degree`, `syntax`…
4. `!polyEquals(poly, target)` ⇒ `wrong` with `formatPoly(poly, var)` as the shown expansion and `diagnoseMismatch(poly, target).tag` as the tag (`sign-whole`, `dropped-gcf`, `extra-factor`, `middle-term`, or null — all four exist in `site/data/misconceptions.js`).
5. `fs = factorStructure(ast, {var})`: `topLevel === 'sum' || typedBack` ⇒ `wrong` "that's the original — factor it"; `gcfIncomplete` ⇒ `almost` "pull the common factor out" (`ctx.strictGCF` ⇒ `wrong`; the "second GCF-incomplete submit is wrong" counter is the grader's); `anyReducible` ⇒ `almost` "one factor still factors"; `hasRational` ⇒ `almost` "use integer coefficients — multiply the 3 in"; else `correct`.
The `roots` grader: split on `, ; or and \n`, strip braces, `parseNumber(token)` (its default `prefix:true` strips a per-token `x =`); `err === 'variable'` ⇒ "enter the roots, not the polynomial". `num`: `parseNumber` + `numEquals(v, answer, tolFor(part))`, `numIsNegOf` for "sign?". `equation`: `parseRational` both sides (rewrite `a:b` → `(a)/(b)` first), `ratFunSub`, then `polyCanonical(num)` vs canonical target or `solveLinear/solveQuadratic(num)` for the numeric fallback; the two-equation system with `parseLinear`.

### Three real defects found by fuzzing, and fixed here
1. **Hang (tab-freezing).** `parseRational('x^1000000')` — reachable from the `equation` field, which parses both sides as rational functions — sat inside `polyPow` multiplying a degree-1 000 000 polynomial and never returned (killed at 12 s). `ratFunAlgebra` was the one algebra with no exponent/degree guard. Fixed: `pow` refuses `k > 40` (`toolarge`) and `deg × k > maxDegree·2` (`degree`), and every `mk()` result is degree-capped. `factorStructure` got the same belt-and-braces cap before `polyPow(f.poly, f.mult)`, in case a caller hands it an AST parsed elsewhere.
2. **Uncaught `RangeError`.** ≈ 2 000 nested parens (or 5 000 leading `-`, or a 5 000-term sum) overflowed the recursive-descent parser's stack — and `evalAst` walks the AST the same way — so `parseNumber` / `parsePoly` / `parseRational` / `parseLinear` threw instead of returning `{ok:false}`, breaking their documented "never throws" contract and crashing whatever widget called them. Also: `factorStructure(null | undefined | 42 | {})` threw `TypeError: Cannot read properties of null (reading 't')` on a widget's empty `raw()`; it now returns `{ok:false, err:'empty'}`.

## Decisions worth knowing
- **Tolerance rule.** S3 says "compare rational-vs-rational exactly, otherwise tol". Read literally that makes `171.001` (rational) fail for 171 while `171.0000001` (float) passes — absurd — and both consumers that landed (T05's `strip.js`, T03's num tests) expect `13.5` ≈ `13` at `tol 0.5`. `numEquals` therefore returns true when the two reduced rationals are identical (no float noise, works at `tol = 0`) **or** `|a − b| ≤ tol`. One rule, no integer special case.
- **NFKC ordering.** The spec claims NFKC maps none of `° º ˚`; in fact NFKC turns `º` into `o`, `˚` into a combining ring, `²` into `2` and `½` into `1⁄2`. All glyph rules run before NFKC and the tests pin it.
- **Layering.** The tokenizer/parser/AST live in `normalize.js` (the leaf) and are re-exported by `poly.js`; the spec's "poly.js has the tokenizer" is satisfied by re-export without an import cycle. One parser, several algebras (`NUM`, `polyAlgebra`, `ratFunAlgebra`, `linearAlgebra`) — a grader that needs a new value domain writes an algebra, not a parser.
- **Grammar superset.** Term-level `/` (so `(180−55)/2` and `x(180−x)/(x(90−x))` parse), unary `+`, `**`. `NUM/NUM` inside an atom still works. `1/2n` = `(1/2)·n` exactly as under the spec's atom rule.
- `middle-term` is strict: same degree, same leading and constant coefficient, interior differs. `(2n−3)(n−3)` for `2n²+3n−9` is therefore tag `null` (its constant is wrong too) — the message still shows the expansion. T03 may loosen it.
- `isReducible` is complete for degree ≤ 3; a rootless quartic that splits into two quadratics reports `false`. No target in this unit is above degree 2.
