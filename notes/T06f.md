## What was built

### `site/data/source-manifest.js` — the literal id checklist (197 rows)
One hand-written row per SOURCE item, never generated from the card files, so the data is checked AGAINST it:
`{ id, skill, sheet, module, src, mock, bonus }`. `skill` is the S2 manifest-line primary skill (`voc/def → VOC`,
`not → NOTE`, `fact → ASN-PLP`, `cls → CLASS`, ang-04 → SEG-ALG, ang-05 → BISECT-Q, ang-10/doc-07 → FIG-ALG,
doc-05 → BISECT-L, ang-09/wp-12 → CS-QUAD, fac → FAC2, quad → QUAD-SOLVE …) and must equal the card's `skills[0]`;
`mock` is the S7 section letters the id can be drawn for (A vocab/notation · B figures · C ASN incl. `fact-*` ·
D angle algebra · E algebra review incl. `quad-*`; `not-06` is `AB`; bonus `null`). Family tiles are listed
separately (`FAMILY_TILES`) because they are tiles, not cards. Counts: voc 23 · not 9 · def 14 · fact 5 · cls 4 ·
ang-wu 5 · ang 10 · doc 3 · wp 16 · asn 36 · qz 18 · bonus 33 · fac 18 · quad 3 = 197 (164 non-bonus).

### `site/js/rarity.js` — the S4 rarity ladder + Foil class rule, pure
Imports nothing, DOM-free, id-pattern based (no data import, so screens can use it without loading the deck).
Class partition: **(a)** ang-wu-1..5, ang-02..11, doc-05..07, wp-01..16 (34) — own template `T-<id>`
(`T-fig-pairs` for the warm-ups) implemented by a generator in the module's `templates` list; **(b)** fac-*,
quad-*, cls-*, not-* (34) — family templates `T-factor-*` / `T-quad-solve` / `T-classify` / `T-notation`, or 3 clean
due-review days; **(c)** asn-*, qz-*, voc-*, def-*, fact-* (96) — 3 clean due-review days; **family** fam-quad-a1 /
a2 / ctx, fam-sys; **null** for bonus-* and unknown ids. `rarityOf()` implements Gold / Silver / Bronze exactly as S4,
including "Gold on wp-*, ang-02..11, doc-06 needs `setupTried`" (a first-try clean clear without a setup attempt is
Silver until the setup is tried — `setupTried` can lift it later, best-ever wins). `foilRule()` is the verbatim
tooltip text per class. Save-schema inputs are the S6 ones: `cards[id].foilProgress = [{ day, via }]` and
`variants[famId] = { clearsGold, goldDays }`.

## Exported API

```js
// site/data/source-manifest.js (ES module, imports nothing)
export const manifest            // frozen [{ id, skill, sheet, module, src, mock, bonus }] × 197, SOURCE order
export const MANIFEST_IDS        // frozen string[]
export const manifestById        // { [id]: row }
export const FAMILY_TILES        // ['fam-quad-a1', 'fam-quad-a2', 'fam-quad-ctx', 'fam-sys']
export const MOCK_SECTIONS       // { A:'Vocab / Notation', B:'Figures', C:'Always / Sometimes / Never', D:'Angle algebra', E:'Algebra review' }
export const SKILL_BY_PREFIX     // { voc:'VOC', not:'NOTE', def:'VOC', fact:'ASN-PLP', cls:'CLASS', fac:'FAC2', quad:'QUAD-SOLVE', bonus:null }
export function expectedSkill(id)   // 'VOC' | … | null (bonus) | undefined (unknown)
export function expectedSheet(id)   // 'VOC' | 'AP-1' | … | undefined
export function isBonus(id)         // boolean (unknown → false)
export function mockSections(id)    // ['A','B'] | [] for bonus / unknown
export function manifestIds({ bonus = true } = {})   // ids, optionally without the Bonus bank
export default manifest

// site/js/rarity.js (ES module, imports nothing, DOM-free)
export const RARITIES = ['bronze','silver','gold','platinum'], FOIL_NEED = 3, FAMILY_PLATINUM_GOLD = 6, FAMILY_PLATINUM_DAYS = 2, FAMILY_STEPS = { bronze:1, silver:2, gold:3 }
export function isClean(clear)              // firstTry === true && hints === 0   (Global rule 8)
export function needsSetupForGold(id)       // wp-*, ang-02..11, doc-06
export function rarityOf(clear)             // { id?, firstTry, hints, attempt?, solutionShown?, setupTried? } → 'gold'|'silver'|'bronze'|null
export function bestRarity(a, b)            // the higher (null-safe)
export function foilClass(id)               // 'a' | 'b' | 'c' | 'family' | null
export function ownTemplate(id)             // class a: 'T-wp-07' / 'T-ang-10' / 'T-doc-05' / 'T-fig-pairs' (ang-wu-*); else null
export function generatorOf(id)             // class a: 'T-cs-lin' | 'T-cs-ratio' | 'T-cs-quad' | 'T-seg-mid' | 'T-fig-bisect-L/Q' | 'T-fig-xlines-Q' | 'T-fig-system' | 'T-fig-pairs'; else null
export function familyTemplates(id)         // class b: ['T-factor-a1','T-factor-a2','T-factor-gcf','T-factor-neg'] | ['T-quad-solve'] | ['T-classify'] | ['T-notation']; else []
export function foilRule(id)                // the verbatim tooltip line ("Platinum = Gold + Foil. Foil: …" / family line / "Bonus bank — …")
export function foilPath(id)                // frozen { id, cls, template, generator, templates, rule, needsSetup, need }   (default export)
export function templateOfVia(via)          // 'T-wp-07#a91f2c' → 'T-wp-07'; 'review' → null
export function foilProgress(id, progress)  // progress: cards[id].foilProgress [{ day, via, firstTry?, hints? }] → { cls, have, need, variants, reviewDays, done }
export function foilEarned(id, progress)    // boolean
export function familyRarity(rec)           // variants[famId] { clearsGold, goldDays[] } → null|'bronze'|'silver'|'gold'|'platinum'
export function tileRarity(id, cardRec)     // cardRec { rarity, foil?, foilProgress? } → best rarity, 'platinum' when gold + Foil
```
Record semantics for `foilProgress` entries (what T10/T09 should write, S6 `cards[id].foilProgress`):
`{ day:'YYYY-MM-DD', via:'T-wp-07#<seed>' }` for a **Gold** Variant clear credited to this card — class (a) counts
entries whose template is the card's `ownTemplate` **or** its `generatorOf` (a T-cs-lin Variant seeded for wp-07 may be
recorded either way); class (b) counts entries whose template is one of `familyTemplates(id)` (being in this card's
list *is* `forCard`); `{ day, via:'review' }` for a clean due-review clear (add `hints`/`firstTry` if the clear was not
clean and it will be ignored). Days are compared as strings — pass local `todayISO()`.

## Decisions worth knowing
- **`keys.test.mjs` is not written** (BUILD-POLICY §1 drops it with the scan fields). Its intent — "no card references
  an image outside what ships" — survives as the coverage test's publication-policy checks (no scan keys in any card,
  no image references in `site/data`, no image/PDF files under `site/`).
- **Mock eligibility is asserted from the manifest today** and from `data/blueprint.js` as well once it exists — the
  test adapts to `eligible(id, letter)`, `candidates(letter, cards)`, or slot objects with `ids` / `sources` / `skills`,
  and logs a diagnostic (never fails silently) when the shape is unrecognised.
- **Own templates are `T-<id>`** for every class-(a) card (S4's literal `T-wp-07`, `T-ang-10`), with `generatorOf(id)`
  naming the S2/S3 generator family that implements it; the test asserts that family is in the module's `templates`.
  `foilProgress` accepts either name in `via` so a save written by T07/T10 under either convention still counts.
- **Class (b) for `quad-*` is `['T-quad-solve']` only** (S4 verbatim); `T-quad-ctx` Variants belong to the
  `fam-quad-ctx` tile. Widen `FAMILY_TEMPLATES.quad` if T11/T12 decide a `T-quad-ctx` rematch should count.
- `rarity.js` is **id-pattern based** and imports nothing; the manifest is the data authority and the rarity test
  cross-checks the two (partition = 164 non-bonus ids exactly). A new id needs a manifest row AND a pattern here —
  the rarity test fails otherwise, on purpose.
- Teacher-flag prints its `FLAG:` lines with `console.log` (they appear as TAP diagnostics only when something
  disagrees) and fails through `assert.deepEqual(takeFlags(), [])`, so the failure message itself lists every flag.
