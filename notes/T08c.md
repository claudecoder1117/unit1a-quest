## What was built

`site/js/widgets/pairs.js` — the `pairs` answer widget. Three ways to answer, one pick stream:

| path | how |
|---|---|
| **wedges** | one delegated `click` + `keydown` listener on the `<svg>`; `wedgeEl(svg, e.target)` resolves the group, `data-name` is the canonical angle. Enter **and** Space work on a focused `.fig-wedge-hit` (Space's default scroll is prevented). |
| **side list** | every angle of the figure as a 44 px pill (`angleOptions(model)`); a pill is a complete answer path on its own, so a figure without wedges still answers the card. |
| **typed field** | `∠GFC` · `angle GFC` · `<GFC` · `GFC` · `m∠GFC` · lowercase · a wedge id (`C-D`), all through T04's `parseName`. One field accepts two names at once (`∠GFC and ∠CFD`, `GFC, CFD`, `GFC CFD`, `∠GFC + ∠CFD`). |

The first pick is **pending**: its wedge fills at 32 %, its pill reads `aria-pressed="true"`, and a live
line says `∠CFG selected — now pick the angle it pairs with.` The second pick completes a pair, which
is graded **instantly** by `gradePairs(part, picks, model, ctx)` and appended as a chip (`✓ ∠EFG + ∠CFG`
/ `✗ ∠BFC + ∠CFD`), with the grader's arithmetic line in the result line under it. Picking the pending
angle again clears it. Tapping any chip re-reads that verdict; hovering one re-fills its two wedges.

Spec rules and where they live:
- **repeated pair is free** — caught *before* it is committed (`applyPick` → `event:'duplicate'`), so it
  costs nothing, never enters `raw()` and never clutters the chips; the message is the S3 one
  ("already used, pick a different pair. That one is free."). `gradePairs`' own duplicate branch still
  covers a replayed `raw()`.
- **malformed name is free** — `parseName`'s message goes under the field (and in the result line);
  nothing is committed, the text stays selected for a quick retype.
- **straight angles** never appear as a wedge or a pill (`angles()` excludes them); typing `∠GFD` gets
  T04's refusal ("…is a straight angle (180°) — FG and FD are opposite rays").
- **∠XFY ≡ ∠YFX** and pair order never matter: every pick is stored as T04's canonical name (outer
  letters sorted) and pairs are keyed order-free.
- **input↔wedge link (S5)**: a resolvable name in the field, a hovered/focused pill, a focused wedge or
  a hovered chip fills that wedge at 18 % (`linked`).

**Verdict colour on a wedge is a FLASH (1 s), never sticky.** This was a real defect caught on the dev
page: a wedge fill paints the *whole* sector (T04), so keeping `ok` on every angle of every found pair
covered the drawing in a green disc. What persists instead is the chip list plus a green outline on
each pill already used. (Shots before/after are in the session scratchpad, not committed.)

`raw()` returns `[[angleName, angleName], …]` — exactly what `js/grader/pairs.js` takes — so a screen
can always re-grade with `grade(part, handle.raw(), { figure: card.figure })`.

## Exported API

```js
mount(el, part, ctx) → handle          // also `export default` and `mountPairs`; T08a's contract
```
`part` = `{ type:'pairs', relation, count, prompt? }` (any `normRelation` alias).
`ctx` (all optional): `{ card, figure|model (a figure SPEC), figureEl|svg (a rendered <svg>), values
(a saved raw() to restore), locked, onInput, onSubmit }`. The widget also fires the base.js bubbling
events `w-input` (every pick) and `w-submit` (when the count is reached).

Handle (base.js `handle()` fills the rest):
```js
el, part, type:'pairs', svg, model
raw() / values() → [[name, name], …]        // canonical names, oldest first
result()        → the last gradePairs() result | null
isComplete()    → result().ok
isEmpty()       → no picks and nothing pending
pips()          → { total: 1, filled: 0|1 }  // S1: a pairs part is ONE pip (index.js pipsFor agrees)
setFeedback(res|null)                        // screen-level verdict line + flash; null clears
lock(on = true) / focus() / clear() / undo() / setValue(picks) / pick(angleName) / destroy()
```

DOM-free helpers (exported for tests and for any screen that wants the same vocabulary):
```js
angleOptions(model) → [{ key, id, name, alias, label:'∠CFD'|'upper-left angle', aria, level }]
createPickState() → { picks:[], pending:null }
applyPick(state, key) → { picks, pending, event:'none'|'pending'|'cleared'|'pair'|'duplicate', pair }
undoPick(state)      → { picks, pending, event:'cleared'|'removed'|'none', pair }
hasPair(state, a, b) · pairKeyOf(a, b)
splitTyped(raw) → tokens          // "∠GFC and ∠CFD" → 2; "angle GFC" stays 1
resolvePick(model, ref) → { ok:true, key, shown, angle } | { ok:false, msg, tags, straight }
figureSpecOf(part, ctx) → spec|null   // by SHAPE: a DOM node is never a spec (see "Gotcha" below)
relationPhrase(relation, count) · progressText(valid, count) · RELATION_WORDS
```

## Decisions worth knowing
- **Instant validation, no submit needed.** A pair is judged the moment its second angle is picked;
  the card screen's Submit still calls `grade(part, raw(), ctx)` and gets the same verdict (the widget
  holds no state the grader cannot re-derive from `raw()`).
- **Canonical names in `raw()`**, not the student's spelling: a saved answer replays byte-identically
  through `setValue()` and through the grader. The student's own wording is kept for messages
  (`parseName().shown`), which is what the chips and the verdict lines show.
- **`pips()` is `{total:1}`** to agree with `index.js`'s `pipsFor` (S1: a pairs part is one pip, however
  many pairs it asks for). Progress is shown as "2 of 3 pairs found" instead.
- **`figureSpecOf` matches by shape.** `ctx.figure` means *the rendered `<svg>`* in base.js and *the
  figure spec* in `grader/pairs.js`; passing the wrong one to `resolveModel` silently yields no model.
  This widget accepts either from either key and never guesses by name.
- **No figure → no crash.** A `pairs` part mounted without a resolvable figure renders one plain line
  ("This question needs its figure, and it did not load…") and a handle whose every method is safe.

  `site/js/gen/figsystem.js:175` has a template literal (`tag: '${x0}_${y0}_…'`) that the tag scanner

  `teacher-flag: ang-wu-*`) were transient — other lanes writing files while the suite ran — and both
  pass now.
- The widget drives wedge state directly on the `<svg>`; it does **not** use base.js's `ctx.onWedge`
  callback (that API only carries the `linked` state, and this widget also needs `selected` / `ok` /
  `bad`). A screen that wants to own wedge painting should hand the element instead.
- A composite angle's wedge is a large sector, so a *selected* composite (e.g. ∠CFG at 154°) tints a
  big part of the figure at 32 %. Checked at 375 px in both themes — the strokes stay readable — but
  if T18 disagrees, the fix is a lower `fill-opacity` for `.fig-wedge.is-selected[data-level]:not([data-level="0"])`
  in figure.css (T04's block, not mine).
