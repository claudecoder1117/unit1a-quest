## 1. What was built

### 1.1 `tests/_helpers.mjs` — the deduped helpers

The helpers that more than one suite had its own copy of. Zero dependencies on `site/` and no top-level side
effects, so importing it is free and it can be used by a test that is deliberately checking what `site/data`
loads. The leading underscore matters: the runner collects `**/*.test.?(c|m)js` and `tests/index.js` imports
exactly `/\.test\.(mjs|cjs|js)$/`, so this file is never run as a test file on any Node version — which is the
trap a test file that exports a helper falls into.

| export | signature | replaced |
|---|---|---|
| `ROOT` | `string` | 8 local copies (`coverage`, `integration-w3`, `integration-w4`, `misconceptions`, `no-random`, `run`, `sw`, `teacher-flag`) |
| `repoPath(...parts)` | `(…string) → string` | new |
| `read(p)` | `(string) → string` | `read` in `integration-w3`, `run`; `src` in `integration-w4` |
| `readIfAny(p)` | `(string) → string \| null` | new |
| `listFiles(dir, re?, {skip}?)` | `(string, RegExp, opts) → string[]` | `walk()` in `no-random` |
| `stripCommentsAndStrings(src)` | `(string) → string` | the exported copy in `no-random` + a weaker regex `stripComments` in `run` |
| `correctRaw(card, part)` | `(card, part) → raw` | **byte-identical 35-line copies** in `coverage` and `mock` |
| `CORRECT_RAW_TYPES` | `readonly string[]` (17) | the inline literal list in `coverage` |

`correctRaw` was the one worth doing: it is the engine behind two different acceptance checks —
`coverage.test.mjs` ("every part of every card grades its own stored answer `correct`") and `mock.test.mjs`
("a perfect Mock scores 100") — so a content change that stops round-tripping now fails in both off one
definition. `coverage.test.mjs` additionally asserts `CORRECT_RAW_TYPES.length === 17`, so a new S3 part type
cannot land without a builder.

`stripCommentsAndStrings` is the stricter character scanner (the one `no-random` had), not `run.test.mjs`'s
regex version, and it now preserves newlines inside block comments and template literals so a scan's line
numbers stay honest. `no-random.test.mjs` re-exports it so anything that imported it from there still works.

**Files touched to wire this up** (deletion of the duplicate + one import line each, all marked `// T17`):
`coverage`, `mock`, `integration-w3`, `integration-w4`, `run`, `misconceptions`, `teacher-flag`, `sw`,
`no-random`. No assertion was changed.

### 1.2 `site/js/store.js` — the unit hand-off (S8 #19)

The save now carries `unitId` and `archive`, and `migrate()` has a second axis: the unit.

```js
export const UNIT_ID = 'u1a';          // the unit THIS BUILD teaches — bump with the data swap
export const LEGACY_UNIT_ID = 'u1a';   // what a save with no `unitId` is assumed to be — FROZEN FOREVER
export const ARCHIVED_KEYS = ['cards','variants','frozen','runs','errors','skills',
                              'forecastLog','placement','jumps','postTest','inProgress'];
export const KEPT_KEYS     = ['v','unitId','profileId','createdAt','settings','xp','streak',
                              'daily','counters','trophies','seedCounter','archive'];

migrate(raw, now?, { unit }?)            → save   // version chain + defaults + (optional) hand-off
archiveUnit(save, { id, skills? }, now?) → save   // the hand-off; idempotent, safe on every load
archivedUnits(save)                      → [{ key, unitId, archivedAt, v, stats, …data }]  // newest first
createStore({ …, unit })                          // default { id: UNIT_ID, skills: SKILL_IDS }; null disables
store.migrateUnit(next?)                 → save   // hand over now, notify('unit'), write to disk
store.flags.archivedUnit                 → string | null   // the unit filed away on this load
```

`ARCHIVED_KEYS ∪ KEPT_KEYS` is asserted to be exactly the save schema, so no key can fall between the two
sets — that assertion is what makes "zero data loss" checkable rather than claimed.

Design notes worth knowing:

* **The spec names five archived keys; eleven are archived.** `skills` had to be (the S8 #19 reset rule is
  only lossless if the old record is kept somewhere), and `forecastLog`, `placement`, `jumps`, `postTest`,
  `inProgress` are unit-scoped and would be silently *wrong* under the next unit's data — a Readiness
  sparkline mixing two units lies, a half-finished run's item ids no longer resolve. All eleven are archived
  before being reset, so the extension costs nothing.
* **`skills` is re-seeded from the archive** with exactly the ids the next unit's `skills.js` reuses. Call a
  Unit-1B skill `VOC` and the student walks in already Mastered; rename it and the record is archived, not
  live. Omit `unit.skills` and every record is carried over (the caller did not say what the new unit
  teaches, so dropping mastery would be a guess).
* **Nothing is ever overwritten.** Archiving a unit id that already has an entry files the second under
  `u1a~2`, `u1a~3`, … — the case where an old Unit-1A save is *imported* into a Unit-1B build.
* **`store.js` now imports `SKILL_IDS` from `../data/skills.js`** — its only content dependency, and the
  reason the hand-off needs no wiring in `app.js`: bump `UNIT_ID` in the same commit as the data swap and it
  happens inside `load()`, written to disk immediately, with `flags.archivedUnit` set for Settings.
* **`applyCaps` does not touch the archive** (it is history, not working state), and `pack`/`unpack` compact
  archived card history the same way live cards are compacted.

**One bug fixed while I was in the file:** `save({ immediate: true })` — and therefore
`update(fn, { immediate: true })` — wrote **nothing** when the state happened to be clean, because `flush()`
is dirty-gated and nothing marked the state dirty on that path. No live caller hit it (`grep` finds
`immediate: true` only in tests, where the surrounding failure modes left `dirty` true), but "write now" must
write. `save()` now marks dirty before flushing.

### 1.3 `.github/workflows/pages.yml` — the gate

`deploy` already declared `needs: test`. What changed:

* **`needs: [test, artifact-policy]`** — two gates now.
* **A matrix, Node 22 and 24.** 22 is the floor the repo targets; 24 catches test-runner semantics drifting
  before a runner bump makes it a deploy-day surprise.
* **"the suite actually ran".** `node --test <dir>` discovers files differently across Node majors (22 expands
  the directory; ≥ 25 hands the positional to the loader, which resolves `tests/index.js`). A version where
  neither path collects anything exits 0 having run nothing, and the deploy sails through. The summary line
  is now parsed and asserted: a `pass` count must exist, `fail` must be 0, and `pass` must be ≥ 1000. The awk
  rule matches both the spec (`ℹ pass 1138`) and TAP (`# pass 1138`) reporters, so it does not care which one
  a given Node picks in CI.
* **A new `artifact-policy` job** enforcing BUILD-POLICY §1 on the exact folder that gets uploaded: no
  raster or PDF file anywhere under `site/`, no `site/content/`, `<meta name="robots" content="noindex">`
  still in `index.html`, and nothing under `source/`, `designs/`, `content/*.png` or `qa/screenshots/`
  tracked by git. The copyright rule is the one thing here that cannot be fixed after the fact once Pages has
  served it.
* **`pull_request` trigger** (tests + policy run, deploy is skipped via `if: github.event_name !=
  'pull_request'`), a top-level `permissions: contents: read`, and `timeout-minutes` on every job.

`node qa/gen-precache.mjs` is deliberately **not** in CI: the Action must not rewrite the repo it is testing.
It stays on the integrator's checklist (`notes/OPEN-ISSUES.md` §F).

```bash
# the artifact-policy job, by hand

git ls-files | grep -E '^(source/|designs/|content/.*\.png$|qa/screenshots/)'                   # must be empty
grep -c 'name="robots" content="noindex"' site/index.html                                       # must be 1
```

The hand-off suite's 13 tests, in order: the two key sets partition the schema · zero data loss (every
archived key byte-identical in `archive.u1a`, every kept key untouched) · the live save is reset and `skills`
keeps exactly the reused ids · omitting `skills` keeps everything · a save with no `unitId` is Unit 1A ·
no-unit and same-unit are no-ops · idempotent and chains 1A → 1B → 1C · a repeat archive lands in `u1a~2` ·
survives pack/unpack/export/import · `applyCaps` leaves the archive alone · a stored 1A save is handed off on
the next open and written back · `store.migrateUnit()` on demand · **this build never archives its own saves**.

The stub Unit-1B "data set" is a literal in the test (`{ id: 'u1b', skills: ['VOC','NOTE','CLASS','FAC1',
'FAC2','TRI-CONG','PROOF'] }`) on purpose: the point is that `store.js` needs nothing from the next unit but
its id and its skill-id list.

   in `notes/OPEN-ISSUES.md` §C with the reasoning: swapping `grader/mc.js`'s `hash53`/`stableOrder` for

   fixtures re-baselined); hoisting `cleanMsg()` out of 8 widget files into `base.js`; hoisting `pickN` into
   `gen/contract.js` and unifying the two generator entry shapes. All three are in files this ticket does not
   own.
2. **The CI matrix has never actually run.** Node 22 is not installed on this machine (only 26.3), so "green
   on Node 22" is argued from the discovery rules plus a clean run of the per-file glob form, not observed.
   The first Action run on `main` is the real proof. If Node 22 surprises us, `tests/index.js`'s header
   documents both paths and the fix is a one-line change to the `run:` step.
3. **The `pass >= 1000` floor in the CI guard is a magic number.** It is there so a discovery regression
   cannot pass as a green build; it needs raising if the suite ever grows a lot, and lowering if a unit swap
   legitimately shrinks it. `docs/next-unit.md` §5 says so.
4. **The archive has no eviction.** "Never deleted" is the spec, and two units are ≈ 1 MB of a 5 MB quota, so
   this is fine for the foreseeable future — but a fourth unit should come with a Settings action that
   *exports first*, then removes. Noted in `docs/next-unit.md` §4.
5. `archivedUnits()` and `flags.archivedUnit` have no UI. Settings (T15) is where a "Past units" list and the
   "Unit 1A is filed away" note belong; the data is there and tested.
