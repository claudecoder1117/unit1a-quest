## What was built

### `js/gen/factor.js` — the factoring family
`(a₁v + b₁)(a₂v + b₂)` drawn answer-backward, so **no prime trinomial can ever be emitted** (the test
re-decides with `poly.js`'s `isReducible`, it does not take the generator's word for it). Every S2 bound is
enforced and asserted: `gcd(aᵢ, bᵢ) = 1`, `a₁a₂ ∈ 1..9` (1 for `a1`, ≥ 2 for `a2`), `|b| ≤ 9`, GCF
`g ∈ {2,3,4,5}`, optional leading −1, variable ∈ `{a,b,k,n,p,v,x}`, every expanded coefficient non-zero
(a real trinomial, never a difference of squares) and `≤ 120`. Gauss's lemma does the work for the GCF: the
product of two primitive linear factors is primitive, so the `g` pulled out really is the greatest common
factor (the test re-checks `gcd` of the inner trinomial = 1).

The answer is emitted **typed** — `target` is a descending integer coefficient vector and `answerTyped` is
`{c, factors:[[a,b],[a,b]]}` — alongside a display string (`−2(p − 5)(2p + 9)`, U+2212). Hints follow the
S3 ladder (GCF → ac-method / product-and-sum → the split middle) and never state the factored form; the
solution does. Each item carries `middle-term` (signs flipped inside), `sign-whole` (negative lead dropped)
and `dropped-gcf` misconceptions with their own lines.

### `js/gen/quad.js` — `T-quad-solve` and `T-quad-ctx`
`T-quad-solve` reuses factor.js's factors with `a ∈ {1, 2}` so every root is an integer or a half (S2's
"integer or .5 answers"); roots are distinct, emitted as typed `Rat`s, and the part carries `poly` (the typed
vector) so the `roots` grader can print "plug it back in". Modes `a1` / `a2` map to the S2 family tiles
`fam-quad-a1` / `fam-quad-a2`.

`T-quad-ctx` is the S3 `rootcase` chain with an optional `equation` setup slot in front. Three stories, each
built so the keep/reject verdict is decided **by construction**:

| frame | story | reject reason |
|---|---|---|
| `rect` | a rectangle (x + p) by (x + q) with a given area | `negative-length` |
| `angles` | two adjacent angles filling 90° or 180° | `negative-angle` · `zero-angle` · **`both-valid`** |
| `zero` | an angle equation whose other root collapses the figure | `zero-angle` |

`both-valid` is a coin flip (~35 % of items), so rejection is never automatic — the rule S2 states for
`T-cs-quad`, applied here because this is the template that teaches it. A both-valid item is ang-10 shaped:
it ends in a `cases` part with one row per root, and its reject menu always carries the
"… is negative so reject it" distractor S3 requires. A one-root item ends in a `multi` of the quantities.
The setup slot's `mustMention` anchors the item's own number (the area, or 90/180), so `x = 9` and the
already-simplified standard form are both caught as `simplified-setup`.

### `js/gen/sys.js` — `T-sys`
Solution `(x, y) ∈ [−9, 9]²` drawn first, constants computed from it, coefficients `∈ [−6, 6]\{0}`,
**det ≠ 0** checked on every emitted item (the test also re-solves with Cramer and compares). Three methods:
`sub` (one equation shown already solved, `y = 3x − 4`), `elim` (one column equal or opposite), `general`
(neither — the student scales first); the hints walk the method the item actually wants. Swapping x and y is
caught structurally by `multi` (`swapped-fields`) and by the item's own misconceptions.

### `js/gen/notation.js` — `T-notation`
A fresh 4–6 letter point set per item (no I, no O). Ten kinds: `ray` (weighted heaviest — B1's elite is
`not-04`), `line`, `seg`, `len`, `ang`, `m`, `plane`, `cong`, `eq`, and `read` (an `mc` of a rendered symbol).
The answer is a canonical `{kind, pts}` / `{kind, sides}` object — the same typed shape the T08d builder
submits — so a Variant and `not-04` are graded by identical code. **The `ray AB ≠ ray BA` trap is on every
ray item**: the reversed build grades `wrong` with tag `ray-order`, the item carries the trap in
`misconceptions[]`, and the test asserts the typed build and the string spelling (`ray BA`) give the identical
verdict. `len` items trap the bar (`bar-on-length`), `ang` items the vertex (`vertex-not-middle`), `cong`/`eq`
the ≅-vs-= confusion.

### `js/gen/vocab.js` — `T-vocab`
Four modes — `mc-def`, `mc-term`, `type` (Damerau ≤ 1 through the `term` grader), `match` (the 6↔6
`termmatchSets`). Every definition, alias, confusable list and match set comes from `data/vocab.js` (T06a);
nothing is re-typed. Distractors are the term's own confusable group and carry `term`, so `mc.js` names the
confusable and derives the tag from its own groups — the generator never invents a tag.

### `js/gen/classify.js` — `T-classify`
One item = one six-measure set with **exactly one 90 and exactly one 180**, at least one acute and one obtuse,
all six distinct and inside (0, 180], usually with a near-boundary measure (88/89, 91/92, 178/179) so
"less than 90" versus "90" is actually tested. Six `classify` parts, one tap each. Boundary slips carry
`boundary-90` / `boundary-180`.

### Registry
`site/data/templates.js` is T07a's; my ten entries live in its object literal with the other eleven. Each
entry carries `forCards` (S4(b) family-templated originals: `fac-*` → the four `T-factor-*`, `quad-*` →
`T-quad-solve`, `not-*` → `T-notation`, `cls-*` → `T-classify`), `needs`, `family` (`fam-sys`,
`fam-quad-a1/a2/ctx`), `label`, `blurb`, `partTypes`, and the variety knobs (`modes` / `frames` / `kinds`).

## Exported API

```js

export function expandFactors({c, factors}) → [A, B, C]      // descending integer coefficients
export function factoredText({c, factors}, v) → '−2(p − 5)(2p + 9)'
export function linText([a, b], v) → '(2p + 9)'
export function targetText(desc, v) → '−4p² + 2p + 90'       // via poly.js formatPoly
export function gcd(a, b) → number
export const VARS, GCFS

// js/gen/quad.js

// js/gen/sys.js
export const templates            // [T-sys]

// js/gen/notation.js
export const templates            // [T-notation]
export function build(rng, {kind?, points?}) → Item

// js/gen/vocab.js
export const templates            // [T-vocab]
export function build(rng, {mode?:'mc-def'|'mc-term'|'type'|'match', key?}) → Item

// js/gen/classify.js
export const templates            // [T-classify]
export function build(rng, opts) → Item
export const BUCKETS              // ['acute','right','obtuse','straight']
```

`gen(rng, opts)` is the shape every descriptor exposes; the registry wraps it into its own
`gen(seed, params)` contract, so callers use the registry:

```js
import { generate, getTemplate } from '../data/templates.js';
const item = generate('T-quad-ctx', 'day-3#2');                          // deterministic per (id, seed)
const forced = generate('T-quad-ctx', 'seed', { frame: 'angles', bothValid: true });
getTemplate('T-sys').modes        // ['sub','elim','general']   — the knobs `params` accepts
getTemplate('T-quad-ctx').frames  // ['rect','angles','zero']
getTemplate('T-notation').kinds   // ['ray','len','ang','line','seg','m','plane','cong','eq','read']
```

Item shape (S2): `{ id:'T-factor-a2#d386a3', template, templateVersion, seed, seedKey, seedTag, module,
sheet, tier, par, skills[], needs[], family?, params, prompt, stem (alias of prompt), figure:null, parts[],
answer, hints[3], solution[{say, math}], misconceptions[{part, field?, answer, tag, msg}] }`.
`params` records every knob the draw chose, so a failing seed is readable without re-running it.

**Typed answers** (S3 "strings in data, typed in gen; `grade()` normalises both"): `factored.target` is a
descending coefficient vector and `answerTyped` is `{c, factors}`; `roots.answer` is `Rat[]`; `multi` field
answers are numbers; `cases` rows and `reject` valid/rejected lists are ASCII strings (`-1/2`), exactly as
`cards/angles.js` writes ang-10's. Display prose uses U+2212 to match the stems.

The T07c block of `tests/gen.test.mjs` (22 tests) is self-contained — its helpers are `t07c*`-prefixed so it
never collides with the shared harness — and pins each of the ticket's named acceptance checks:

* **no prime trinomials ever** — every emitted target goes through `poly.js` `isReducible(polyPrimitive(...))`;
  also `gcd(aᵢ,bᵢ) = 1`, `|b| ≤ 9`, `a₁a₂ ∈ 1..9`, GCF ∈ {2,3,4,5}, and the inner trinomial primitive.
* **det ≠ 0** — recomputed as `a₁b₂ − a₂b₁` on every `T-sys` item, plus Cramer re-solving to the emitted pair.
* **`ray AB ≠ ray BA` traps present** — ≥ 20 ray items per sweep; each reversed build is `wrong` + `ray-order`,
  each item carries the trap, and `{kind:'ray',pts:[B,A]}` and the string `"ray BA"` give identical verdicts.
* **typed coefficient vectors grade identically to string fixtures** — the same 8 probes graded against the
  typed vector, a `Poly` object and a plain string target must agree on `kind`, `credit`, `tags` and `msg`.
* **`T-quad-ctx` keep/reject stories** — all three frames drawn, `negative-length` / `zero-angle` /
  `both-valid` all reached, both-valid vs one-rejected is a coin flip (both > 10 in 250 seeds), the whole
  `setup → roots → reject → cases|multi` chain round-trips, and swapping keep/reject is caught with
  `rejected-valid-root` / `kept-invalid-root`.

Plus, for every template: determinism (`generate(id,s)` deep-equals itself and replays from the stored seed),
the structural contract (hints[3], solution ≥ 2 steps, unique part ids, known skills, tier 1–4, par > 0), no
`NaN`/`undefined`/`null`/`[object Object]` in any student-visible string or any value, every emitted tag in
`data/misconceptions.js`, every part type reaching a registered grader, and ~200 hostile inputs per template
that must never throw and never grade `correct`.

## Open issues

1. **`T-notation` / `T-vocab` emit `figure: null`.** S2 says "random 4–6 point figures, relabelled". The
   letters are generated and carried (`item.params.points`, `item.letters`, and `part.letters` for the
   builder's tappable palette) but no figure MODEL is emitted, because figure specs are T04/T07b territory
   and inventing a second spec dialect here would have collided. The items read fine without one
   ("Points Z, F, Y and K are labelled in the figure. Write the name of the ray with endpoint F…"), but a
   small fan figure would be better. See Requests → T07b.
2. **A both-valid `T-quad-ctx` item has `misconceptions: []`.** Its natural error — stopping at one case — is
   already diagnosed by the `cases` grader (`missing-case`, with the reveal on the second miss), so there was
   nothing honest to add. The one-root frames carry `kept-invalid-root` and `stopped-early` entries.
3. **`T-quad-ctx` never produces the `angle-over-180` reason.** With two adjacent angles summing to 90 or 180
   and both positive, neither can exceed 180 — the reason is unreachable by construction. It is present as a
   *distractor* on angle items. A frame that reaches it (a measure built from x with no sum constraint) is a
   possible follow-up.
4. **The GCF templates never pull out a monomial** (`8n² + 4n` → `4n(2n + 1)`): S2 fixes the GCF as
   `g ∈ {2,3,4,5}`, a constant, and every Kuta §6 item with a GCF (fac-08, 09, 18) is constant-GCF too. If
   the teacher's test includes a monomial GCF, that is a new `kind` in `factor.js`, not a change to these.
5. **`T-vocab` items for terms outside the four S2 confusable groups carry no tagged misconceptions** (there
   is no catalogued tag for, say, "vertex confused with side"); the distractors still carry their `why` line,
   which is what the student sees. `mc.js` derives the tag where a group exists.
6. **Draw budget**: the worst template uses ~91 of the 200-draw cap over 5 000 seeds, so the fixed exemplars
   are effectively unreachable in normal use. They are still exercised indirectly (every template's exemplar
   path is code-reachable and structurally identical to a normal item), but no test forces the fallback — a
   future test could call the internal builder with a pre-exhausted Rng.
