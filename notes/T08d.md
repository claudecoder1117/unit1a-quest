these widgets render), `site/js/widgets/base.js` (T08a's contract), `site/js/grader/index.js` (T03).

Eight widgets, one per word part type. Every one is a pure view over `(part, ctx)`: it renders the part,
collects an answer in the exact shape that part's grader documents, and paints back whatever
`grade()` returned. **No widget re-derives a rule** — which chips to ask for, which slot is next, whether
a spelling counts, what the answer was: all of that is read off the grader result.

## Contract

`mount(el, part, ctx) → handle`, exactly T08a's contract (`site/js/widgets/base.js` header):
`raw()`, `setFeedback(res)`, `lock(on = true)`, `focus()`, `destroy()`, `isEmpty()`, `pips()`,
plus `el / part / type`. All eight also implement `values()` (a JSON-safe snapshot for a save) and take
`ctx.values` back on mount to restore it. They are registered in T08a's `site/js/widgets/index.js`
`LAZY` map already — **no wiring edit was needed anywhere**.

`pips()` always reports `{total: 1, filled: 0|1}` to agree with `index.js`'s `pipsFor()`, which is what
T09 uses to draw the pip row *before* mounting. Internal progress is exposed separately where it exists
(`strip.progress()`, `termmatch.left()`, `cloze.blanks()`).

### ctx keys these widgets read

| key | meaning |
|---|---|
| `seed` | option / chip / definition order — **pass the same seed to `grade()`** or an index resolves against a different order (mc, asn, termmatch) |
| `mode` | `'card' \| 'full36' \| 'mock' \| 'blitz'` — asn passes it straight to its grader |
| `settings` | `{askReasonOnMiss}` — asn |
| `onSubmit(detail)` / `onInput(detail)` | T08a's `wire()`; the widgets also fire bubbling `w-submit` / `w-input` |
| `values` | restore a saved answer (never re-submits it) |
| `locked` | mount read-only |
| `keys` | a shared key row handle (the dock's) — strip and cloze attach their numeric fields to it; without one they render their own |
| `dock` | passed through to `keepVisible()` |
| `shortcuts: false` | **new flag, mine** — turn off this widget's single-key shortcuts (see "Requests") |
| `onWedge(ref, on)` | strip's `multi` slot fields (doc-05's halves carry `wedge`) |
| `prose: false`, `copy: false` | strip: suppress the prose block / the Copy button |

## Exported API

Every module exports `mount` **and** the same function as `default`.

```js
// js/widgets/asn.js      raw() → 'A'|'S'|'N'  |  {verdict, reason}   (once a chip is picked)
mount(el, part, ctx) → handle & { stage(): 'verdict'|'reason' }
// js/widgets/mc.js       raw() → {text, index}
mount(el, part, ctx) → handle & { options(): [{text, ok, …}] }        // display order, what the grader indexes
// js/widgets/classify.js raw() → 'acute'|'right'|'obtuse'|'straight'
// js/widgets/term.js     raw() → string
// js/widgets/termmatch.js raw() → {[termText]: definitionText}
mount(el, part, ctx) → handle & { layout(), left() }
// js/widgets/cloze.js    raw() → [value per blank, in text order]
mount(el, part, ctx) → handle & { blanks(): number }
// js/widgets/notation.js raw() → {kind, pts} | {kind:'cong'|'eq', sides:[o,o]} | null
mount(el, part, ctx) → handle & { markup(): string }                  // the mini-markup on screen
// js/widgets/strip.js    raw() → {[slotId]: value}
mount(el, part, ctx) → handle & { progress(): {done, total} }
//   slot values: pick/verdict → option text · num → string · multi → {fieldKey: string} · chips → [text]

// js/widgets/shortcuts.js
export function bindShortcuts(map, {root = document, active = () => true}) → unbind
export function isTextField(node) → boolean
export function isShown(node) → boolean
```

## Behaviour worth knowing (and why)

- **asn is one tap.** A verdict tap submits immediately. The one-line reason is *read*, never tapped — it
  comes back on the result and is printed under the buttons. The three chips open only when
  `result.askReason` is true (a wrong verdict with `askReasonOnMiss`, or Full 36); a chip tap submits
  `{verdict, reason}`. A graded verdict disables the three buttons either way, because S3's wrong line
  names the right letter — the item is settled; only the chip row stays live. `result.disputed` prints the
  ⚑ note **after** grading, never before (qz-04's note contains the answer).
- **mc / classify keep the item alive after a miss.** Their graders name the confusable or the rule and
  never the answer, so only the picked option is struck out and disabled; everything else stays tappable
  for attempt 2. `asn` is the opposite (see above) and locks.
- **term** has no datalist and `autocomplete=off`: a browser autofill dropdown would hand over the word.
  A correct-but-misspelt answer shows `Yes — spelling: collinear` from `res.note`.
- **termmatch is tap-a-term-then-tap-a-definition.** No dragging: a 6 × 6 drag surface is unusable at
  375 px and impossible from a keyboard; every cell is a real `<button>`. A definition can be used once —
  assigning a taken one moves it. After a grade, matched pairs lock and only the wrong ones are cleared.
- **cloze renders the sentence, not a list of fields.** Blanks sit inline; the chip row belongs to the
  *active* blank only (def-01..14 have 4 options each — three rows at once do not fit at 375 px). Correct
  blanks lock. Inline `[does/does not]` choices work because `choicesFor()` reports them.
- **notation is a builder, not a text field** (the acceptance case): decoration row (↔ ‾ → AB ∠ m∠ ▱,
  plus ≅ / = only when the answer is a relation) + letters from `part.letters`, with the build re-rendered
  live through `mathfmt` above the rows — the student watches FB grow its arrow. Unfilled letter slots show
  `?` so the decoration always spans something visible. `⌫` removes the last letter, then the decoration,
  then (on side 2) the relation. Keyboard: A–Z appends, Backspace deletes, Enter submits.
- **strip grades left to right and never decides anything itself.** It submits the whole
  `{slotId: value}` object and renders `result.slots[].state`: `locked` rows show their label with the body
  hidden (the student sees the shape of the explanation without being able to jump to the verdict),
  `pending` is the one open row, `ok` / `revealed` are settled and lose their Check button; a revealed row
  prints `ANSWER <value>`. On `complete` the prose sentence renders with a Copy button.
  `pick`/`verdict` taps auto-submit; `num`/`multi`/`chips` carry a Check button (Enter does the same).
- **Keyboard** (S5 AAA): asn `a/s/n` + `1/2/3`, mc `1–5`, classify `a/r/o/s` + `1–4`, notation letters,
  Enter to submit in every text field. `shortcuts.js` ignores every shortcut while a text field has focus
  (S3 edge case), while a modifier is held, and while the widget is locked or off-screen.
- **Restore never re-submits.** `ctx.values` sets the controls and stops there (an early version of asn
  fired a submit on mount; fixed).
- **Motion / colour**: only `flash()` from base.js (the 120 ms shake / 180 ms pulse), and every state also
  carries a glyph (✓ ✗ ← ⓘ) or a strikethrough — never colour alone.

   everything `site/` serves, is green, and the misconception scanner reports no tag from my files.
   631 of 633 pass.
2. **The 200 ms double-submit guard in `base.js`'s `wire()` is time-based, not target-based.** In a strip,
   consecutive submits are on *different* slots, so a very fast tap-tap (pick → YES) inside 200 ms is
   silently dropped. It cost me half an hour on the dev page before I found it. Realistically a student
   reads between slots, so I left the shared guard alone rather than opting out — but if T09 sees a
   swallowed strip tap, this is why.
3. `cloze` restores typed blanks by value and chip blanks by text; a chip blank whose saved text is not in
   its option list is ignored (silently) rather than shown as an unknown value.
4. `notation` supports `cong` / `eq` builds (two sides, a side switcher) but **no card in the bank uses
   them** — only `len`, `ray`, `ang` (not-03..06). That path is exercised by construction, not by content.
5. Several widgets on one screen each bind their own shortcuts. No card in the bank has two parts of the
   same word type, so `a/s/n` can never be ambiguous today; a queue screen that shows two at once must pass
   `shortcuts: false` on the inactive one (see Requests).
