### Ownership note (read this first, integrator)
The ticket lists six files plus the one-line app.js wiring. I added a **seventh file, `site/js/sw-register.js`**,
and left app.js at exactly one line. The update flow is a small state machine (installing / waiting /
controlled / dismissed) with its own DOM (the pill) and its own public API for Settings; putting it in
`app.js` would have been ~90 lines in the file every other ticket reads, and putting it in `settings.js`
would tie a global concern to a screen that is only sometimes mounted. Nobody else owns the file and
nothing else imports it except my own two modules. Move it if you disagree — `registerSW()` is the only
entry point.

## Exported API

### `js/sound.js`
```js
export const CUES = ['correct','wrong','mint','level','combo']
export function isSupported() → boolean          // false under Node / no WebAudio; never throws
export function isQuiet(now = new Date()) → boolean        // days.isQuietHours: local hour ≥ 22
export function soundEnabled() → boolean                   // settings.sound
export function isAudible(now = new Date()) → boolean      // soundEnabled ∧ !isQuiet ∧ isSupported
export function setSound(on) → boolean                     // writes settings.sound through store.update
export function unlock() → boolean                         // create/resume the context from a user gesture
export function play(cue, arg) → boolean                   // true only if sound was actually produced
export function combo(n) → boolean                         // play('combo', n)
export function close()                                    // release the audio hardware
export default { … the same }
```
**How screens use it:** call `play('correct')` / `play('wrong')` unconditionally right after a verdict —
it is a no-op when sound is off, muted or unavailable, and it returns `false` so nothing has to branch.
`play('mint')` belongs on the Page-Summary tile mint (T10/T11), `play('level')` on a level-up (T09),
`combo(n)` on a clean clear that increments the combo (T09; pass the combo count **after** the increment).
Call `unlock()` from the first tap of a run if you want the very first cue to be dead on time; otherwise
`play()` resumes the context itself.

### `js/sw-register.js`
```js
export async function registerSW() → state                 // app.js calls this once; safe everywhere
export function swState() → { supported, registered, controlled, updateReady, installing,
                              version, cache, files, scope, error }
export function subscribe(fn) → off                        // fn(swState()) on every change
export async function checkForUpdate({ throttle = false }) → 'update'|'current'|'unsupported'|'throttled'|'error'
export function applyUpdate()                              // SKIP_WAITING → controllerchange → reload
export async function clearCaches() → number               // delete every packet-* cache + unregister
```
Also reachable at `window.packet.sw` for QA. `registerSW()` does nothing (and reports why in
`state.error`) on `file://`, without `navigator.serviceWorker`, or when the document is outside the
worker's scope — which is what keeps the dev pages under `qa/` clean.

### `sw.js` message protocol
`postMessage({type:'SKIP_WAITING'})` → the waiting worker activates.
`postMessage({type:'VERSION'}, [port])` → `{type:'VERSION', version, cache, files}` back on the port.

### `js/screens/settings.js`

```js
export function mountSettings(params, query, ctx) → (el) => cleanup    // the router contract (notes/T01.md)
export default mountSettings
```

```js
export const ROOT, SITE, SW_PATH, SHELL_FILES, SCAN_DIRS, EXCLUDE
```

## Decisions worth knowing

- **The pill lives under the header, not at the bottom.** The Answer Dock owns the bottom of the Card,
  Boss and Mock screens; a floating pill over the Submit button would be the worst place in the app for
  it. When the Settings toast and the pill are both up, `body:has(.sw-pill:not([hidden])) .set-msg`
  drops the toast below it.
- **The worker never swaps itself in.** `sw.js` has exactly one `self.skipWaiting()` and it is inside the
  `message` handler; `controllerchange` only reloads when the student pressed Reload (`reloading` flag),
  so the first install — which also fires `controllerchange` via `clients.claim()` — never reloads a page
  mid-answer. A test asserts both.
- **`cache.add` per path, not `cache.addAll`.** `addAll` is all-or-nothing: one stale path would abort the
  install and leave the student with *no* offline app. Now a bad path is logged and everything else is
  cached. `{cache:'reload'}` on each request so an install right after a deploy stores the new bytes
  rather than the ≤ 600 s-old ones.
- **Runtime caching as well as precaching**, so a file that somehow is not in the list still works
  offline after it has been fetched once. The list is still enforced, because "after it has been fetched
  once" is exactly the guarantee airplane mode does not give you.
- **The export is live, not a snapshot.** First implementation serialised the save when the card was
  built, so changing the daily goal and tapping Download handed you the *old* goal — caught by the
  browser driver, not by a test. The box, the size line and the blob behind the link now refresh on every
  save change (coalesced 250 ms), in place, so a half-typed paste in the Import box is never wiped.
- **Both Readiness formulas are printed from `js/readiness.js`'s own `FORMULA_FULL` /
  `FORMULA_PROVISIONAL` / `BANDS`** (T10 asked for exactly this), and the live number is computed here
  rather than read off the header, so landing straight on `#/settings` shows the truth instead of `—`.
  The band ranges ("< 50 · 50–69 · 70–84 · ≥ 85") are derived from `BANDS`, not retyped.
- **Reset is a two-tap inline confirm, not `window.confirm()`** — testable, styleable, and the safe choice
  (Cancel) is the plain button while the destructive one is the red outline.
- **The theme control is three real radios** inside a `role="radiogroup"` (arrow keys work); the switches
  are real checkboxes with `role="switch"`, invisible over a drawn track, 56 × 44 px hit area.
- **Sound is greyed *and* muted after 22:00, not disabled-forever**: the preference keeps its value and
  comes back tomorrow (S7's soft close — "the app says stop without locking the door").
- **No `apple-touch-icon-180.png`** — see Requests.

## Open issues

1. **The precache list goes stale every time another lane adds a file under `site/`.** That is the test
   working, not a bug, but it means `node qa/gen-precache.mjs` has to be run (and the one-line diff
   committed) whenever `site/js|css|data|assets` gains a file. It was in sync at 105 paths when I
   finished. Consider adding it to the integrator's checklist; I deliberately did not put it in
   `.github/workflows/pages.yml`, because CI should not rewrite the repo it is testing.
2. **`readVersion()` needs a controlled page.** On the very first load (before any reload) the About card
   says "caching now — offline from the next reload" and shows no cached build, because the page is not
   yet controlled. That is accurate, not a placeholder, but reviewers should not read it as a bug.
3. **The pill is dismissed per page load** (`✕` hides it until the next visit). There is no "remind me
   later" persistence — deliberate: the save is not the place for it and a deploy is rare.
4. **`settings.js` is a static import in `screens/index.js`**, so `readiness.js` (and through it
   `skills.js`, `source-manifest.js`, `schedule.js`) is on the boot module graph. T10's `home.js` puts it
   there anyway, so this costs nothing today; if the boot graph is ever trimmed, `readiness` is the one
   import here worth making lazy.
5. **Storage-blocked case**: if `store.blocked` is set (a save that could not be *read* is never
   overwritten), Settings still offers Import and Reset — both deliberately lift the block, which is
   T01's documented behaviour. The About card's "Saving" line reports `memoryOnly` / `corruptRecovered`
   but not `blocked`; add it if T01's flag is ever surfaced elsewhere.
