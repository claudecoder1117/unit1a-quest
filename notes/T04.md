### The generic instance (why the grader can never be fooled by the drawing)
Rays are grouped into components by `lines` (opposite rays) and `rightMarks`; component 0 holds the first ray, every
other component is *free*. In the generic instance each free component is turned by 9.37° (× 0.7 per extra
component) — F1's C lands at exactly **35.37°**, as the spec says — capped at half the smallest gap to a ray of another
component so the cyclic order (and every angle's identity) is unchanged. A second instance turns by 7.13° (× 0.6).
**`supplementary` / `complementary` hold only when the sum is 180 / 90 in both instances**, so no single nudge can fake
a sum; `sum` (drawn) feeds the feedback line, `sumGeneric` is exposed for tests. `linearPair` / `vertical` / `adjacent`
are pure ray-sharing predicates. Cross-vertex pairs on a poly are never measure-related (F2's angles at A and D sum to
180 only because BD ∥ AE, which this unit never asks).

### Label placement (svg.js)
Expression labels start on the bisector at `arcR + 16` and slide outward in 4-unit steps; each radius is also tried
at ±1…±3 steps of `span/10` off the bisector, scored `r + 16·|k|`, so a wide label in a narrow wedge (ang-10's
`2x² − 4x + 3` in the 26° ∠AFE) hugs one side instead of running out of the viewBox. A box must clear every stroke by
6 units, its own arc by 4, the viewBox inset (6) and every placed box by 6. If it can only be placed by moving a
ray letter, that letter is reflected to the other side of its ray (kept only if the flipped spot is clean). Then the
figure's manual `labelOffsets.angle[id]` is added and the box is clamped into the viewBox. `layout().exprLabels[].fits`
is false when nothing clean was found (never true for any shipped case — tested).

Mono text metrics are 0.62 em per glyph including spaces and superscripts (JetBrains Mono / Menlo / SF Mono advance
0.60–0.61); the browser-measured report on the dev page agrees (0 clipped, 0 overlaps at 375 px).

## Decisions worth knowing
- **C at 26°, not 31°.** The transcript measured F1's ray C at ≈ 26° (±2°); COMPOSED's 31° was the old estimate. Every
  relation is structural, so nothing in the grader depends on it; only drawn measures in feedback lines change (26 / 64 / 116 / 154).
- **Canonical angle names sort the outer letters** (`CFD`, `AFE`, `CFG` after rename). `data-name`, aria-labels, `pairs()` keys and
  `normalized` all use them; `parseName().shown` keeps the student's spelling for messages ("∠EFA and ∠AFC …").
- **Labels in card specs use the displayed letters** (after rename). No shipped card renames AND labels; generated variants
  (T07b) build both in the letters the student will see.
- **Ticks are opt-in on F2** because the print has none; `F2_TICKS` exists for a solution step ("B and D are midpoints, so …").
- **`notToScale` auto-detects numeric disagreement** so cls-01/cls-03 (given 31° / 121° on the 26° drawing) show the chip without
  the card saying so; an explicit `notToScale:false` still wins.
- `kind:'almost'` for a valid-but-incomplete pick: the part is not done, but nothing is charged (Global rule 2). A wrong pair is
  `kind:'wrong'` (charged); a repeat of a wrong pair is `almost` (free) — a student cannot be charged twice for one idea.
