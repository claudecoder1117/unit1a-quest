## What was built

`js/screens/run.js` is **one screen for every run kind**, so no run type ever grows a route of its own
(S1: "every run type named anywhere in S1/S7 mounts here and nowhere else"). It is three things stacked:

1. **Pure rules** (DOM-free, all exported, all unit-tested): the queue builder for every kind, the BLITZ
   round machine, the JUMP placement write, the Summary arithmetic, the run record.
2. **A card-driven runner** that embeds T09's `createCardView` one item at a time and owns only the queue,
   the mode flags and the Summary. Every save write for a graded card still happens in exactly one place
   (card.js): XP, combo, mastery, Leitner, rarity, foil, error log, daily goal.
3. **A bespoke BLITZ renderer** — the one kind that cannot use the card view (see *BLITZ* below).

| kind | what it runs | notes |
|---|---|---|
| `page` | `resumePage(save) ?? startPage(save)`, `markItem` per item, `requeueReview` on a missed review, `finishPage` at the end | quittable at any card in one tap; progress is already saved |
| `blitz` | M1 / M3 / M9, 60 s (M1, M3) / 90 s (M9), tier ≤ 2 | −3 s + 1.2 s lockout per wrong, 3-in-a-row ends it, 250 ms auto-advance on correct |
| `jump` | **delegated** to `onboard.js#mountJump` (T14); run.js's own 10-item runner is the fallback | pass = m 80 / n 5 / `placedAt` / `jumps[M]` |
| `drill` | 5 Variants of one skill (originals when a skill has no generator: ASN-PLP / ASN-ANG) | `drill:true` → `scope 1`, no Variant discount (S1) |
| `daily` | 5 items, seed `cyrb53(dateISO)`, one module each | +20 XP once a day (`daily[today].dailyDone`) |
| `full36` | `asn-01…36` in sheet order, untimed | `mode:'full36'` → the asn grader asks the reason chips on **every** item |
| `missed` | `missedOriginals(save)` 5 at a time | each item runs as a review |
| `upgrade` | every Bronze/Silver original (Bronze first), optional `:sheet` | hints off (S7) |
| `baseline` | **delegated** to `mock.js#mountBaseline` (T13) | |
| `night` / `morning` | **delegated** to `night.js#mountRunKind` (T14) | it does its own Post-test check |
| `post` | **delegated** to `night.js#mountRunKind` — not an S1 run kind, so it is not in `RUN_KINDS`; the deep link still works | |

### The Page Summary (S1 "Page ends on a Summary")
XP (tweened, and by construction the sum of `xp.js`'s own `xpFor()` values) · flawless count (`isClean`,
not "cleared") · cleared/total · time · **tiles minted** (a before/after diff of `tileRarity` /
`familyRarity`, rendered with T11's own `.tile` + `.tile-sheen` and a 460 ms flip, staggered 90 ms) ·
rarity histogram · **skill bars animating old → new** (rendered at the old value, then transformed to the
new one on the second rAF, with the number tweened) · **Readiness delta** (`before → after (+n)`, plus
`readinessDelta(save)` as a "since your last day" line **only when it differs**) · Binder coverage · plan
state (today's XP vs the goal, `nextAction(save).label`) · "Another page" / "Binder" / "Today".
Empty sections are not appended at all, so they cannot eat a grid gap.

### BLITZ — why it does not use the card view
A 60-second recall sprint cannot afford a result strip, a par line and a Continue tap, and the −3 s
penalty + 1.2 s input lockout + 3-strike end have no home in the card timeline. So BLITZ renders a lean
prompt + answer row (mc buttons / A-S-N / a numeric input), grades through the **same**
`grader/index.js` with `ctx.mode:'blitz'` (which is what makes the asn grader drop reasons and chips,
S3), and writes the outcome itself through `recordBlitzAnswer`:

* **score-only** (S1): no XP, no combo, no level-up.
* but a right answer **is a clear** — S4 Readiness `C` and S7's plan `R` both say "a Full 36 or BLITZ clear
  counts", and S4's Foil class (c) counts a BLITZ clear of a card that was **due** (so `foilProgress`
  gets `{day, via:'review'}` only when the card was due). Rarity is written through `rarityOf` +
  `bestRarity`, otherwise the Binder would show an unplayed tile for a card the fill % counts as cleared.
* a wrong answer still moves mastery (score 0 through the normal EMA) and still applies the Leitner
  `wrong` outcome; it never writes rarity.
* the key badges on every option are bound to real keys (`1–9`, `a`/`s`/`n`), because a badge that does
  nothing on a keyboard is a lie.

## Exported API

```js
// constants
BLITZ = { penaltyMs:3000, lockoutMs:1200, strikes:3, advanceMs:250, maxTier:2, modules:['M1','M3','M9'], defaultLimitMs:60000 }
JUMP  = { items:10, pass:8, m:80 }
DRILL_ITEMS=5 · DAILY_ITEMS=5 · DAILY_XP=20 · MISSED_PAGE=5 · UPGRADE_MAX=12 · FULL36_IDS:string[36]
RUN_KINDS: readonly string[]            // page blitz jump drill daily full36 missed upgrade baseline night morning
isRunKind(kind) → boolean
kindMeta(kind) → { title, back, mode, hints?, drill?, delegate? } | null
delegateOf(kind) → { mod, fns:[string], fallback:'stub'|'self' } | null   // includes 'post'

// screen
mountRun(params, query) → (el) => cleanup        // params = { kind, id? }, seed via query.get('seed')

// seeds / items
runSeed(kind, { id, seed, save, today }) → string        // ?seed= wins; daily is always cyrb53(dateISO)
seedTagOf(seedStr) → string                              // 6 hex chars for the header corner
cardItem(card, role, extra?) → queueItem                 // the shape page.js writes
variantItem(template, seed, role, extra?) → queueItem
variantsFrom(templateIds, count, seed, { role, params, forCard }) → queueItem[]
templatesOfModule(moduleId) → string[]                   // modules.js first, the registry as fallback
originalsFor({ moduleId, skill, save }) → card[]         // uncleared first, bonus never
shuffled(list, rng) → list                               // deterministic Fisher–Yates (rng.int(0, i))

// queues
buildRun(kind, save, { id, seed, now, today }) → {
  kind, id, seed, seedTag, title, subtitle, back, mode, hints, drill, items, meta, limitMs, empty }
upgradeTargets(save, { sheet }) → string[]               // Bronze first, then Silver
dailyQueue(save, { seed, today }) → queueItem[]

// BLITZ
blitzPool(moduleId, { rng, save, count }) → entry[]       // { key, cardId?, template?, seed?, type, tier, skills, stem, part, card|item }
createBlitzRound({ limitMs, penaltyMs, lockoutMs, maxStrikes, startedAt }) → {
  state, remaining(now), locked(now), snapshot(now), tick(now), answer(ok,{now,key}), stop(now) }
recordBlitzAnswer(save, entry, { ok, ms, now, today }) → cardRec|null    // call inside update()
cardRecordOf(save, id) → cardRec                                         // the S6 default record

// JUMP
jumpPassed(correct, total?) → boolean
applyJump(save, moduleId, { correct, total, at }) → { passed, moduleId, skills }   // inside update()

// Summary
xpOfResult(result) → number
summarizeRun(results) → { count, cleared, missed, clean, firstTry, xp, ms, rarities, accuracy }
tileIdsOf(items) → string[]          // originals + each Variant's forCard + its family tile
tileSnapshot(save, ids) → { [id]: rarity|null }
mintedTiles(before, after) → [{ id, from, to, fam }]
skillDeltas(beforeStates, afterStates, ids?) → [{ id, name, from, to, untested }]
makeRunRecord({ kind, id, seed, seedTag, startedAt, submittedAt, results, items?, extra }) → runRecord
pushRun(save, rec) → rec             // stamps `n`; store.applyCaps keeps the newest 40
```

## Decisions worth knowing

1. **BLITZ pays no XP but does write clears.** "Score-only" (S1) vs "a BLITZ clear counts" (S4 `C`, S7 `R`,
   S4 Foil class (c)) — this is the only reading that satisfies every line. If the integrator wants a
   round-end XP bonus instead, it is one `pushRun` neighbour in `endRound()`.
2. **`jump` is delegated to T14's screen.** T14 shipped `onboard.js#mountJump` (the screen every Binder
   tile links to) while this ticket was in flight, with the same placement semantics (`writeSkill` sets
   `n = PLACEMENT_N = 5` and `placedAt`; `jumps[M]` on a pass). Running two JUMP screens would be the real
   defect, so run.js delegates and keeps its own 10-item runner as the fallback (`fallback:'self'`).
   `applyJump` here stays exported and tested — it is the fallback's write and the acceptance fixture.
3. **JUMP counts first-try clears.** "≥ 8/10" is read as eight items answered right first time; a retry is
   not a correct answer. T14's screen counts the same way (`rec.result.firstTry`).
4. **The Page's review re-queue happens before the pointer moves** (`requeueReview(s,{idx})` then
   `markItem(s,r,{idx})`, one `update()`), so the copy always lands after the current item and the block
   ends only when every review item has been answered correctly (S1 step 4).
5. **`full36` rides on `opts.mode = 'full36'`**, which card.js passes straight through to `ctx.mode` and the
   asn grader turns into "chips on every item". No new flag was needed in card.js.
6. **Nothing here re-implements a save write that card.js already owns.** The only direct writes are the
   BLITZ path, the JUMP placement, the Daily Challenge bonus, `finishPage`, the run record,
   `checkDailyGoal` and `logForecast`.
7. **`session.combo` is never reset between items** (notes/T09.md's request) — a Page is one combo run.

## Open issues

1. **`nextAction(save)` composes a whole page** just to print the Summary's "Next:" line. It is one call
   at the end of a run, not per frame, but if T10 ever adds a cheap `nextActionLabel(save)` this should use it.
2. **BLITZ recycles its pool** (`items[i % items.length]`) rather than reshuffling when it runs out. With
   28 (M1) / 54 (M9) / 40 (M3) entries against a 60–90 s round that cannot be reached in practice.
3. **The Daily Challenge bonus is +20 XP flat** (S4) and is banked on finishing, not per item; a quit
   mid-run banks nothing. `daily[today].dailyDone` guards a second bank.
4. **`missed` shows the first 5 of the list**, not a rotating window — re-running it after clearing gives
   the next 5 because `missedOriginals` shrinks. If a student stalls on one item it stays item 1.
5. **No `?seed=` on `#/run/page`.** The page's identity is `inProgress`, not a URL seed (S1: "the seed
   alone cannot rebuild a half-answered page"). A `?seed=` on any other kind is honoured.
6. The `post` kind is reachable only as a delegate (`#/run/post`); it is deliberately not in `RUN_KINDS`
   because S1 does not list it as a run kind.
