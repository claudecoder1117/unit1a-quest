### 1.1 The plan (S7), exactly

```
R = Σ over uncleared, unplaced, non-bonus originals of {1: ⅙, 2: ½, 3: 1, 4: 1}[tier]
    + 3 per uncleared family tile          (Bonus never; a Full-36 / BLITZ clear counts as a clear)
q = ceil(R / max(D − 1, 1)), capped 40;  12 with no test date
warn   ⇔ q > 12      target = warn ? 12 : q
```
On a fresh save **R = 62.5** (S7 says "≈ 61"): 105 tier-1 recall cards weigh 17.5, 52 tier-2 weigh 26, the
3 + 4 tier-3/4 diagram cards weigh 7, the four family tiles weigh 12. That gives **q = 11 at D = 7 with no
warning** (the S8 acceptance), **7 at D = 10**, and 13 → warned-and-lowered-to-12 at D = 6. Unweighted it
would have been 164 / 6 = 28 every week, which is why S7 weights it.

The lowering is **visible**, never silent: the strip prints "13 new a day is more than a day holds — the
target is 12", then the three things that actually change (vocabulary/notation to flash only, tier-4 to one
a day, reviews untouched). `composeOpts(save)` is what Home / `run.js` should hand `startPage`.

### 4.1 Two deliberate decisions worth knowing

* **The Night mini-mock is scored on FIRST TRY only.** It runs on `createCardView` with `mode:'mock'` and
  `hints:false`, which still shows the per-item result strip (T13 owns the real no-feedback Mock engine). If
  the run were scored on "cleared", a student who retries after seeing the feedback would inflate the
  `accuracy` that Readiness's `A` term reads (× 0.8). Scoring the first answer makes the number honest
  whatever the screen shows. See Requests → T13.
* **A failed JUMP writes nothing.** S1 only defines the pass case ("≥ 8/10 marks the module placed,
  m = 80 with n = 5"). The ten cards have already moved mastery through the normal EMA path as they were
  answered; stamping a flat `m` on top would double-count the same sitting and could wipe a genuinely
  earned 70 down to 0 for one bad run. The screen says "Nothing is lost".

### 4.2 Smaller decisions

* **`placedAt` only on a clean item.** `schedule.needsMet` treats *placed* as satisfying an item-level
  `needs:`; a wrong placement item must not unlock `ang-10`.
* **The ASN placement item is a real original**, not a Variant — M9 has no generator. It therefore counts
  toward Readiness `C` when cleared, which is correct ("`C` counts only Cards actually cleared").
* **`Rexact` vs `R`.** ⅙ is not representable, so 105 of them land a few ulps off. `q` divides the raw sum
  (bit-identical to `page.js`'s own sum, so the strip and the composer can never disagree); `R` is the
  rounded number the UI prints. A drift test pins both.
* **The plan strip reuses T10's `.plan-strip` / `.plan-pills` / `.plan-pill` classes** and only adds the
  gap pill, the ♛, the warning line and the lowering list — one look, one stylesheet block.
* **The run chrome is one segmented progress bar** (a tick per item, coloured by outcome) rather than a
  continuous bar *plus* ticks: the sticky head has ~105 px to spend on a 375 px screen.
