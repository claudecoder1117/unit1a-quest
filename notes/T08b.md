# T08b — Widgets: polynomial + equation

`site/js/widgets/factored.js` and `site/js/widgets/equation.js` (COMPOSED S8 #8b; S3 "Parts · factored" and
"Parts · equation"), plus the `/* === T08b === */` block in `site/css/widgets.css` and
`tests/widgets-t08b.test.mjs`.

Both widgets are built on **T08a's `js/widgets/base.js`** (`h`, `field`, `msgLine`, `keyRow`, `stateOf`,
`flash`, `wire`, `handle`, `promptLine`, `label`, `plain`) and are mounted through **T08a's
`js/widgets/index.js`**, whose `LAZY` map already points at both files — *no edit to `index.js` was needed and
none was made*. Grading is never re-implemented: `factored` drives its preview with `preview()` from
`js/grader/factored.js` (i.e. `js/grader/poly.js`), and `equation` reads its live hint from `parseEquation()`
in `js/grader/equation.js`. Every verdict comes from `grade()`.

> `js/widgets/` and no widget contract, so T08b first created a registry + toolkit of its own in

## 1. What was built

### `js/widgets/factored.js` — the live "expands to" preview

One `base.field()` text box, a key row, a preview line, a verdict line.

* **The preview line** (`.w-preview`) re-runs `preview(part, raw)` on every keystroke and paints one of four
  states, read from `data-state`:

  | state | when | look |
  |---|---|---|
  | `idle` | box empty | `expands to · · ·`, dimmed |
  | `ok` | parses, does not match | `expands to 6a² + 25a + 25` in text colour |
  | `match` | **expands to the target** | the whole line + the input border turn `--ok`, a `✓` appears, one 180 ms `flash(pv,'ok')` pulse |
  | `err` | not parseable *yet* | the parser's own words, muted italic (`Missing a closing )`, `Use the variable a`) |

  The preview answers exactly one question — *does this expand to the original?* It never judges **form** (a
  GCF left inside a factor, a factor that still factors, fractional coefficients) and never says "wrong", so a
  student is never told they have missed while they are still typing. `(4b+20)(4b−5)` therefore previews green
  and *then* grades `almost` "Pull the common factor out of (4b + 20): 4(b + 5)." — which is the S3 behaviour.
* **Screen readers**: the preview is the input's `aria-describedby` (so it can be read on demand), and a
  separate `.sr-only` polite region speaks **only on the match transition** — announcing every keystroke would
  make the field unusable.
* **Key row**: `( ) − <var> <var>²` (+ `/` when the target has fractional coefficients). The square key is
  labelled `a²`, not a bare `²`, which is nearly invisible at 44 px; it types `^2`, which `normalize.js` reads.
* On a clear, the verdict line says `Factored completely — nothing left to pull out.` (the grader's own
  `✓ <expansion>` is already on the green preview line, and `msgLine` draws its own glyph).

### `js/widgets/equation.js` — skip-setup, two-equation entry, the Mock's 40 % split

* **skip setup** — offered on Cards (`ctx.skip !== false && !ctx.mock && !ctx.boss && part.optional !== false`;
  the 16 `wp-*` setups carry no `optional` flag and are skippable by that default, the 12 `ang-*`/`doc-*` ones
  say `optional:true`). While skipped: `raw()` is `null` (which is what `combineCredit()` drops), the boxes dim,
  the key row hides, the button becomes **Write the setup**, and the line reads *"Setup skipped. Gold on this
  card needs the setup attempted once — "Write the setup" brings it back."* (S3: Gold on these cards requires
  `cards[id].setupTried`). It fires `ctx.onSkip(handle)` and a bubbling `w-skip` event.
* **two-equation entry** — `doc-07` (a `system` with no single-variable `canonical`) opens with two labelled
  boxes; `ang-02` (system **and** canonical) opens with one plus a **"+ second equation"** button, and the
  second box also opens itself when a grader result comes back `err:'two-vars'` / "needs two equations".
  `raw()` joins the filled boxes with `", "` — the shape `js/grader/equation.js` documents. `setRaw()` splits a
  joined string back into the boxes.
* **the Mock's 40 % split** — with `ctx.mock`, a badge reads `40% · 2 of 5 pts` before the submit (from
  `ctx.points ?? 5`) and, after it, `Setup: 2 of 2 pts — 40 % of this question.` from `result.share`/`credit`.
  The skip button is not offered in a Mock or a Boss, where the slot is required.
* **the live hint** (`.w-eq-hint`) is about **form only**, never correctness: `One equation in x. Keep the 180
  in it — write it before simplifying.` → `Ready to check — one equation in x.` → the parser's own message when
  it does not parse (`Write an equation — it needs an = sign.`, `One variable, or two equations.`) → and, when
  the typed equation has already been simplified past a `mustMention` number, the amber
  `Ready to check — but keep the 180 in it: write the equation before you simplify.` That last one surfaces
  S3's structural guard *before* it costs an attempt. The hint steps aside once a verdict is showing and comes
  back on the next keystroke.
* **Key row**: `( ) − = <var>` + `<var2>` on a system + `<var>²` when the item's answer is quadratic + `/` when
  any accepted form is a fraction + `:` when the canonical itself is a fraction equation (S3 rewrites `a:b` as
  `(a)/(b)` in this part only).

### CSS — `site/css/widgets.css`, block `/* === T08b === */`

Only the two widgets' own furniture: the preview line's four states, the equation head/badge/hint/skip/split,
and one cross-lane override documented in place —
`.w-factored .w-key, .w-equation .w-key { flex: 0 1 auto; }`, because T08a's `flex: 1 1 auto` stretches the one
or two keys that wrap onto a second row to half the screen each. Everything else (`.w`, `.w-field`, `.w-input`,
`.w-keys`, `.w-key`, `.w-msg`, `.w-mark`, `.w-prompt`, `is-shake/is-pulse/is-amber`) is T08a's block, untouched.
*(An earlier version of this block carried `:where()` zero-specificity fallbacks for those primitives, written
while T08a's CSS did not exist. T08a's block landed, so the duplication was removed — its header comment still
refers to them.)*

## 2. Exported API

Both modules export `mount` (named **and** default), which is all `index.js` needs, plus the pure helpers the
test file uses.

```js
// js/widgets/factored.js
mount(el: HTMLElement, part, ctx = {}) → handle
keysFor(part, v = varOf(part)) → Array<string | {label, insert, aria}>   // the item's insert keys

// js/widgets/equation.js
mount(el: HTMLElement, part, ctx = {}) → handle
keysFor(part, v, w /* second variable, or null */) → Array<string | {label, insert, aria}>
promptOf(part, skippable: boolean) → string      // part.prompt/label minus the "(… skippable …)" aside
```

`handle` is T08a's contract (`raw`, `setFeedback`, `lock`, `focus`, `destroy`, `isEmpty`, `pips`, `el`, `part`,
`type`) plus:

| both | |
|---|---|
| `setRaw(v) → handle` | fill the box(es) — restore saved `work`, or "retry same answer" |
| `clear() → handle` | empty the box(es) + the verdict |
| `keys` / `keysEl` | the widget's own `keyRow()` api / its element (`null` when the screen passed `ctx.keys`), so a dock can re-parent it |

| `factored` | |
|---|---|
| `preview() → {ok, text, match, msg}` | the current preview, straight from `grader/factored.js` |
| `previewState() → 'idle'\|'ok'\|'match'\|'err'` | what the line is showing |
| `target` | the target polynomial as text (`−6a² − 25a − 25`) — never the answer |

| `equation` | |
|---|---|
| `skipped` (getter) | `true` while the setup is skipped (`raw()` is then `null`) |
| `skip(on = true) → handle` | toggle it (no-op when the slot is required) |
| `openSecond() → handle` | show the second equation box |
| `split(result) → {share, points, slotPts, earned}` | the Mock arithmetic behind the badge |

**ctx** (all optional): `onInput({raw, part, type, handle})`, `onSubmit(…)` — T08a's `wire()`, which also fires
bubbling `w-input` / `w-submit` on the widget root; `onSkip(handle)` + a bubbling `w-skip`; `mock`, `boss`,
`points` (Mock item points, default 5); `keys` (a shared key row — the dock's — used instead of drawing one),
`keyRow:false` (none at all); `skip:false`; `values:{[part.id]: '…'}` or `value`; `locked`, `skipped`,
`autofocus`.

Both widgets own S3's **200 ms double-submit guard** on the submit path (Enter in the box; on a system, Enter in
box 1 moves to box 2).

## 3. How to test

```sh
cd /Users/oliver/Projects/unit1a-quest
node --test tests/                 # 629 tests, 0 fail (5 of them tests/widgets-t08b.test.mjs)
node --test tests/widgets-t08b.test.mjs
```

`tests/widgets-t08b.test.mjs` covers the DOM-free decisions — which keys every one of the 18 `factored` parts
and all 28 `equation` parts offers (variable present, `=` present, `²`/`/`/`:` only where the item needs them,
row never longer than two phone rows) and the "skippable" rewrite of the prompt. It also pins that both modules
stay import-safe in Node (no `document` at module scope).

**Browser (how the ticket's 375 px check was run, and how to redo it).** The dev page `qa/t08b.html` was
created for this and **deleted again** as the ticket requires; it was ~80 lines: import `byId` from
`site/data/cards.js`, `mountPart`/`loadFor` from `site/js/widgets/index.js` and `grade`/`ready` from
`site/js/grader/index.js`, `await ready` and `await loadFor([{type:'factored'},{type:'equation'}])` (after which
`mountPart` is synchronous and returns the real handle), then mount ~18 cases into `.case` boxes with
`id="case-N"` and report into `window.__t08b`:

```sh
node qa/shot.mjs "/qa/t08b.html" /tmp/t08b.png --root --w 375 --h 950 --click "#case-9 h2" --eval "window.__t08b"
#   --root serves the repo root (a qa/ page importing ../site/…); --click scrolls a case into view
#   (an anchor in the URL does not: the page builds its DOM after load)
```

What that check found and what was fixed, all verified in the browser afterwards:

1. `root.append(null)` for an absent prompt/key row printed the literal text **"null"** on every widget → the
   child list is filtered.
2. `@media (max-width: 420px) { .w-eq-head { flex-direction: column } }` turned the prompt's `flex: 1 1 200px`
   basis into a **200 px height**, opening a huge hole above the boxes → the head wraps instead of stacking;
   nothing in this block switches to a column.
3. The verdict line printed **two glyphs** (`✓ ✓ −6a² …`) because the graders' correct messages carry their
   own `✓` → glyphs are stripped, and a clear now reads `Factored completely — …` / `That's the setup.`
4. Wrapped keys stretched to half-width; the square key `²` was nearly invisible; "Equation 2" was labelled
   while "Equation 1" was not → `flex: 0 1 auto` in this block, `a²` labels, `labelField()` on `openSecond()`.
5. The stale live hint sat under a fresh red verdict → it clears on a verdict and returns on the next keystroke.

Final measurements at 375 × 950 (18 widgets on the page, light **and** `--dark`): **zero console errors, zero
failed requests, no horizontal overflow**, every visible key ≥ 44 × 44 px, every input 48 px, and a real key
press verified end to end — with the caret mid-string, clicking `)` inserted at the caret via `setRangeText`,
**focus stayed in the input** (so the OS keyboard would not close), and the preview flipped to `match`.

## 5. Open issues

1. **The lazy proxy in `index.js` forwards only part of the contract.** `mountPart()` on a not-yet-imported
   type returns a placeholder handle that forwards `raw / setFeedback / lock / focus / isEmpty / pips / values /
   activePart / destroy` — **not** `setRaw`, `skip`, `openSecond`, `preview`, `split`. Screens must
   `await loadFor(parts)` before `mountPart` (which `index.js`'s own header recommends) or those calls are
   missing. See Requests.
2. **The key row is drawn inline, above the box, not in the sticky dock.** S5 wants it in the Answer Dock with
   `visualViewport` handling; `base.js` has all of it (`createDock`, `keyboardInset`, `keepVisible`), and this
   widget already supports it — pass `ctx.keys = dock.keys` and it feeds the dock's row instead (and
   `handle.keysEl` is `null`). **T09 decides**; nothing here needs to change.
3. **`setupTried` is not written here.** The widget reports the attempt (`w-submit`, `ctx.onSubmit`) and knows
   when it was skipped (`handle.skipped`); writing `cards[id].setupTried` on any non-skipped submit is T09's
   (S3's Gold rule). The skip note in the UI already tells the student what it costs.
4. **A 7-key row wraps to two lines at 375 px** (e.g. `wp-11`: `( ) − = x / :`). Deliberate — keys keep their
   44 px target rather than shrinking, and nothing scrolls sideways.
5. **`ang-02` accepts either a single equation or a system**, so its second box is opt-in. If T09 finds students
   miss the "+ second equation" button, calling `handle.openSecond()` when the card is a system is one line.
6. **No `points` source yet.** The Mock badge falls back to 5 points per item (S3's "2 of its 5 points"); T13
   should pass the real `ctx.points` if Mock items are ever worth something else.
