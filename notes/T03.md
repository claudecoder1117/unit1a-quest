# T03 — Numeric graders + dispatcher

Owner files: `site/js/grader/{num,multi,roots,reject,cases,ratio,equation,factored,index}.js`, `tests/roots-cases.test.mjs`,
`tests/equation.test.mjs`, `tests/golden.test.mjs`, `notes/T03.md`. Spec: COMPOSED S8 #3; S3 "Parts" num / multi / roots /
reject / cases / equation / factored / ratio + "Hints & solutions"; S6 test list (roots-cases / equation / golden). BUILD-POLICY §1
(nothing here touches scans), §2 (ES modules, no deps, no `Math.random`), §3 (`node --test tests/` green).

Every grader is a pure, DOM-free ES module returning the S3 shape `{ok, kind:'correct'|'wrong'|'almost'|'malformed', credit:0..1,
msg, tags:[], normalized, …extras}`; `malformed` and `almost` never consume an attempt (Global rule 2); strictness lives in the
`kind` (Boss/Mock return `wrong`, never charge for an `almost`). No regex lookbehind, no `Math.random`, no import outside `site/`
(`num.js` → `normalize.js`; the others → `num.js` + `poly.js`; `reject.js` → `rng.js` for a deterministic menu order). All nine
modules were parse-checked in Chromium with `qa/shot.mjs --eval` (every import ok, `missing = []`).

### `site/js/grader/num.js`
```js
grade(part, raw, ctx) → {…, value, text, answer, via?:'misconception'|'distractor'|'sign'|'generic', bonus?, main?}
  // part {answer|answers (any-of), tol?, asks?:['comp','supp'], distractors?:{angle, comp, supp, smaller, larger, …},
  //       bonus?:[{key,label,answer}], misconceptions?, wrongMsg?, okMsg?}
  // raw  string | number | Rat | {value} | parseNumber result | (with bonus) {value|answer|main, [bonusKey]…} | {value, bonus:{…}}
// helpers (shared by the sibling graders)
result(kind, msg, extra), isBlank(v), parseValue(raw, opts) → parseNumber shape, toVal(x) → Rat|number|null, show(x) → string,
tolOf(part, ctx), isStrict(ctx), escalate(ctx, key) → n, misconceptionsOf(part, ctx), inScope(m, {part, field}),
matchMisconception(list, v, tol, scope) → {tag, msg, entry}|null, cap(s), chainOf(asks), describeChain(chain),
diagnoseDistractors(part, v, ans, tol) → {msg, tags}|null, parseFailMessage(p, raw)
```
Chain semantics: `asks` = `['comp','supp']` ⇒ chain `angle → comp → supp` ("the supplement of the complement"); `['smaller','comp']`
⇒ `smaller → comp`. A value equal to an earlier stage → "That's the complement — the question asks for the supplement of the
complement (180 − 68.5)." (penultimate stage) or "That's the angle itself — keep going: complement, then its supplement." (earlier);
tag `gave-angle` / `gave-smaller` / `gave-larger` for a base stage, `stopped-early` mid-chain; an off-chain distractor → "That's the
supplement — the question asks for …" (`gave-supplement` …); `used-90-for-supp` / `used-180-for-comp` when `v` = 90 − prev or
180 − prev on the final step and nothing else matched; then "Sign?" (`sign-flip`); then a generic line. A card / generator
`misconceptions[]` entry (in scope) always wins and its `msg` is used verbatim.

### `site/js/grader/multi.js`
```js
grade(part, raw, ctx) → {…, fields:[{key, label, state:'ok'|'wrong'|'blank'|'malformed'|'filled', ok, kind, msg, tags, normalized, value, wedge, bonus}],
                         normalized:{key:text}, fill?:{key:text}, autoSplit?:true, answer? (on correct)}
  // part {fields:[{key,label,answer,tol?,wedge?,bonus?,asks?,distractors?}], orderFree?, tol?}
  // raw  {key: value} | [values in order] | "(-10, 45)" / "30 and 60" (one string for the whole part, graded as an attempt)
valuesOf(part, raw) → {values, whole}
```
kind: any wrong field → `wrong` (credit = ok/total); else a non-blank unparseable field → `malformed`; else nothing right → `malformed`
"Type an answer."; else a required field blank → `almost` "1 of 2 ✓ — fill in the other angle." (free, correct fields lock); else
`correct` (blank bonus fields noted). A true mutual swap always gets "That's the complement — it goes in the other box."
(`swapped-fields`) on both fields; a one-sided swap gets it unless the card wrote its own line for that value.

### `site/js/grader/roots.js`
```js
grade(part, raw, ctx) → {…, normalized:[texts], values, found, extras, missing:number, total, code:'ok'|'subset'|'extra'|'empty'|'polynomial'|'parse', submits?}
  // part {answer:[…] (strings or typed), var?, tol?, poly?|target?|equation? (for the substitution line)}
  // raw  string | string[] | (Rat|number)[]
splitList(raw) → tokens, stripWrappers(s), parseRoots(raw, tol) → {ok, values, texts} | {ok:false, err, msg, token},
polynomialOf(part, answers) → Poly|null, substitution(poly, v, value) → '2(4)² − 5(4) − 3 = 9, not 0'
```
Subset: `almost` (credit = found/total, tag `forgot-second-root`, the card's line when it has one) on the first submit;
`wrong` on the second (`ctx.state['<partId>:subset']`) or at once under mock / boss / strict; never under `sandbox`.

### `site/js/grader/reject.js`
```js
grade(part, raw, ctx) → {…, normalized:{keep, reject, reason}, verdictsOk, reasonOk, roots:[{value, text, keep, valid}], reasonKey}
  // part {of, valid:[…], rejected?|invalid?:[…], reason, reasonKey?, distractors:[…], tol?}
  // raw  {keep:[…], reject:[…], reason} | {verdicts:{text:'keep'|'reject'}, reason} | {decisions:[{root, keep}], reason} | [{root, verdict|keep, reason?}]
  // ctx.roots — the roots found in the roots stage (defaults to valid ∪ rejected)
REASONS, reasonId(reason, part) → {id, text}, expectedReason(part) → id, menu(part) → [{text}], parseRaw(raw, part)
```
Reason ids (= content `reasonKey`): `negative-length` `negative-angle` `angle-over-180` `zero-angle` `not-a-solution` `both-valid`
`neither`. A pick equal to the item's `reason` text is right; a pick equal to a `distractors[]` text is wrong even when its words map
to the right id; otherwise the id decides. credit: 0 (verdict wrong) / 0.5 (verdict right, reason wrong or missing) / 1.

### `site/js/grader/cases.js`
```js
grade(part, raw, ctx) → {…, rows:[{x, value, matched, extra, ok, cells:{key:{state, ok, kind, msg, normalized, value, wedge}}}],
                         missing:number, reveal:{x}|null, code:'ok'|'open'|'missing-case'|'wrong'|'parse'|'empty', submits?}
  // part {of, cols:[{key, label?, wedge?, type?:'num'|'verdict'|'root', tol?}], rows:[{x:'3', CFD:'9', …}], tol?}
  // raw  [{x, …cells}] (one object per tab; the widget fills x from the tab) | {rows:[…]} | {'3':{…}, '-1/2':{…}}
parseVerdict(raw) → 'YES'|'NO'|null, rowsOf(part, raw)
```
credit = correct cells / (rows × value columns). A row **present** with a known x and blank cells is `open` (almost, "x = 3 ✓ —
now fill in the x = −1/2 case" — the x is on the tab, not a reveal); a row **absent** from the submit is the another-case path:
first `almost` "There's another case — the quadratic has a second root." (tag `missing-case`, x withheld), second (or strict)
`wrong` "What if x = −1/2? Work out that case too." + the card's `missing-case` line + `reveal:{x:'−1/2'}` — the widget creates
the tab. Wrong cells beat missing rows; malformed cells beat both.

### `site/js/grader/equation.js`
```js
grade(part, raw, ctx) → {…, share:0.4|1, normalized, poly:'x − 17'|null, system:boolean, matched:'canonical'|'alternate'|'system'|'roots'|null,
                         solved?:string, code:'ok'|'simplified'|'wrong'|'trivial'|'constant'|'parse'|'empty'|'bad-part'}
  // part {var, canonical:string|string[]|null, alternates?:[string | {canonical, mustMention?, roots?}], mustMention?:[180], roots?:['17'],
  //       system?:['x+y-90','y-2x'] (LHS − RHS forms), vars?:['x','y'], symmetric?|orderFree?, optional?, misconceptions?}
  // raw  string: '180 - x = 10 + 9x' | '(180−x):(90−x) = 5:2' | 'x + y = 90, y = 2x' | '180 - x = 10 + 9x, x = 17' (trailing solving ignored)
parseEquation(raw, {var}) → {ok:true, kind:'single', poly, den, letters, numbers, eqs} | {ok:true, kind:'system', forms, vars, …} | {ok:false, err, msg}
equivPoly(P, C) → bool, rootsAgree(P, roots) → bool, solveSystem(forms, vars) → {x, y} | {dependent} | {inconsistent}
```
Order: parse (malformed: `empty` `no-equals` `equals` `no-var` `two-vars` "one variable, or two equations" `wrong-var` "use the
variable x" `too-many` `toolong`, or a system-only item answered with one equation) → zero polynomial ("true for every x") →
card misconceptions (equivalent-to-answer traps by wording, others by polynomial equivalence; `gives` appended when present) →
canonical / alternate equivalence, else the roots fallback → the `mustMention` guard (`simplified-setup`) → correct "Setup ✓";
otherwise the 90 ↔ 180 detector (`used-90-for-supp` / `used-180-for-comp`), then "That gives x = … — check which side is the
supplement" (degree 1) or a generic line. Systems: with `part.system`, solve both (Cramer) and compare the solution point (the swapped
point is accepted when an alternate names x the other way or `symmetric`/`orderFree`); without it, eliminate the second variable and
compare the resulting x-polynomial with the canonicals. `mustMention` is checked on the typed text (every standalone number token).

## Decisions worth knowing
- **Answers are never in `msg`.** Every grader returns `answer` (a display string) for the solution / reveal screens; the student-facing
  line never contains it. The only reveal is `cases`' second missing-case miss (S3), exposed as `reveal:{x}`.
- **Card misconceptions win** over the grader's own diagnosis when in scope (`{part, field}`), and their `msg` is used verbatim — the
  content tickets wrote item-specific lines (note: some of them name the answer or the missing root; see Requests → T06b/T06c).
- **Per-part escalation lives on `ctx.state`** (`'<partId>:subset'`, `'<partId>:gcf'`, `'<partId>:missingCase'`). The dispatcher creates
  `ctx.state` on the ctx object it is given, so T09 should keep **one ctx object per part** across submits (or pass its own `state`).
  `ctx.sandbox` never escalates. Grading is a pure function of `(part, raw, ctx.state)`; the 200 ms double-submit guard belongs in the
  widget — a repeated *identical* subset submit is meant to become `wrong` (S3), so the dispatcher does not memoise it away.
- **`num` bonus fields** (ang-09 / ang-11 `bonus:[…]`): blank never blocks `ok`; a wrong bonus makes the part `almost` (free) with the
  main value still marked right (`main.ok`); `credit` follows the main value.
- **`multi` whole-part strings** (`(-10, 45)`) are a deliberate full answer and graded as an attempt; the free auto-split applies only to
  the per-field submit shape (one field holding two numbers, a sibling blank).
- **`equation` systems and naming.** ang-02's `x + y = 90, x = 2y` (x = the larger) is accepted because the card's alternate canonical
  roots include 60; doc-07 (no alternates) is strict. A system item answered with a single equation is `malformed` (incomplete, free).
- **The `mustMention` guard runs only on an equivalent setup** (`x = 17`, `9x² − 450x = 0`); a wrong equation gets the wrong-equation
  line instead (the guard tag is added when it also lacks the number).
- **`middle-term`** is looser than T02's `diagnoseMismatch`: same degree, same leading coefficient, same |constant| → `middle-term`
  (so `(2n−3)(n−3)` for `2n² + 3n − 9` is tagged, as the S3 example implies); anything else is `wrong-factors`.
- **T02's open issue is closed**: `3 -1/2` is two roots (whitespace + signed number splits), `30 60` too, `5 1/2` stays a mixed number.
- The tag scanner (T06g) reads every string inside `tags.push(…)`: never push a literal that is not a tag (the chain-stage names
  cost one red run mid-ticket; hoisted).

## Open issues
1. **`roots` credit on a subset** is `found/total` (0.5 for one of two) while `kind` is `almost`/`wrong`; the Mock's per-item scoring
   (T13) decides whether partial credit on a roots item counts — `combineCredit` just averages what it is given.
2. **`equation` on a Card** never reveals the canonical; a third wrong shows the card's `solution[]` (T09). `optional:true` is honoured
   only in the empty-field message and in `combineCredit` — the "skip setup" button and `setupTried` are T08b/T09.
3. `rootsAgree` uses float evaluation for irrational intended roots (none in this unit; generated items have integer / half-integer roots).
4. `equation` treats letters case-insensitively (normalize.js lowercases), so `X` is `x`; a stray `y` in a one-equation answer is
   "one variable, or two equations" even on a word problem — deliberate (S3).
5. `reject.menu()` is provided for T08a; its order is seeded by `part.id`, so every card shows the same order every time (no `Math.random`).
