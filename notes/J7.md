## 1. What was built

### `site/js/job/index.js` — the collection, and the only consumable

68 entries, one per tag in `data/misconceptions.js`, grouped by that file's own 11 `AREAS`. No new
taxonomy: the area comes from the catalogue, the wing from `guard.wingOfTag` (G10 #15), and the record
is G7's six fields exactly, `days` a **count** and never an array (G12 #18).

Every write is **pure** — `trigger()`, `resolve()`, `spend()` and `mint()` return a *new* save and
mutate nothing, the contract `crew.allocate()` and `guard.pushHeat()` already ship. The module reads no
clock: a day is always passed in as an ISO string, because G3.7 proof 5 forbids any payoff term in the
layer from reading elapsed time, and the suite greps the file for `Date` / `now` / `elapsed` /
`performance` as identifiers.

**The seal, as a state machine.** `resolve(day)` sets `cleared`, counts the resolution, and counts the
day when it differs from `lastDay`; it seals at `resolved ≥ 3 ∧ days ≥ 3`. `trigger()` on an unsealed
tag zeroes `resolved`, `days` and `lastDay` — that *is* "with zero re-triggers in that window", expressed
in a record that only holds a count and a date. `triggered` is a lifetime count and never restarts,
because it is what the tell ranks by. A sealed tag is retired for good: a later trigger counts and the
cell never re-opens.

**The tell is skill-keyed** (G4, G10 #26). `tellFor(save, skillId, opts)` counts, out of `save.errors` —
the log `screens/card.js logError` already writes — how often each of the 68 tags has been triggered
**on that make**, drops every tag the index records as sealed or resolved, and returns the most-triggered
survivor. Ties break by the most recent trigger, then by catalogue order; there is no random number
anywhere. Attributing an error line to a make needs an id→skills lookup, and the caller passes the one it
already holds, exactly as it does for `call.qHatFor` (notes/J2.md "qHatFor needs a card index"):
`tellFor(save, 'FAC2', { cards: byId })`. With no index the answer is an honest `null` with
`source: 'no-index'`, never a guessed tag.

**Backchecks** live here because G7 gives them no other DOM-free home (§6 Open issues). `spend()` moves
the counter and nothing else in the save; the stake half is `econ.settle({ shielded: true })`, which J1
already ships, and the `calls[]` entry is written by the caller **unchanged** — this file cannot reach the
rating window at all, and the suite greps it to prove that.

### `screens/stats.js` — three panels and the crew grid, no new route

`st-ledger` (records, the rating line with its `n/50`, both Elo numbers, Backchecks held, and the crew
grid) and `st-index` (68 cells in 11 areas) are new `section()`s of `#/stats`; the reliability +
calibration block sits *inside* the existing Bests section, immediately after the Mocks table, because a
Call and a Mock prediction are the same kind of claim scored by the same `call.credit`. Two new jump
chips. Everything is gated on `settings.game !== false`: with the layer off the screen is byte-for-byte

No new CSS. Every panel is built from classes the app already ships (`.st-table`, `.table-wrap`,
`.st-bars`, `.st-pattern`, `.st-area`, `.mono`, `.muted`, `.fs-1`), because `css/screens.css` is J12's
(§7 Requests). Cells carry `data-state` / `data-tag` / `data-wing` so J12's block can colour them.

### `screens/settings.js` — the switch and the five panels

`The Job` card with one switch, default ON (absent means on, `settings.game !== false`), which repaints
the screen. Then, in the exact style of "How Readiness is computed":

1. **How the Call is scored** — both ladders as a table, `EV = q·W − (1 − q)·P`, all three carry
   indifference points, `c(p, o) = 10 − 40(p − o)²` with the propriety derivation, all three Brier
   indifference points, the two disagreement bands **computed by `call.disagreementBands()`**, and the
   EV-max table at six values of `q` with the argmax rung. This is the one place the EV-max rung may
   appear before a call, because it is attached to no target (Global law 6); `js/screens/settings.js` is
   already on `job-call.test.mjs`'s allowlist for exactly that.
2. **How the Guard draws** — `y = project((1 − ε)·x̂ + ε·uniform_n, 0.75)`, the water-filling pseudo-code
   **carrying notes/J3.md §5.3's clarifying sentence** (`an index that has been capped stays capped`), ε
   per rank, the stake weighting `ωⱼ = min(postedⱼ, 0.25·Σₖ postedₖ)`, the token/guard multipliers, the
   fixed point `yᵢ = 1 − k/vᵢ`, and the Elo expectation with the vault-grade bands and the flow control.
3. **How the payout ladder works** — the rung table with what the study layer records, `LADDER`,
   `ρ_eff = LADDER[max(0, rung − crew rank)]`, the crew ranks and the HELD chain-hold at chain ≥ 3, the
   capacity formula, `m_chain`, `PUSH − BAG`, and both published `q*` forms with the fee/completion/commit
   prices.
4. **How posted is computed** — `posted = round(L · scope · wing · cold · tell · ×2)`, both Δloose
   branches, and a legend for `L`, `scope`, the capped `cold`, the live-only `tell`, `wing` and the 1-in-6
   `×2`, plus the Backcheck rules.
5. **How the rating is computed** — `rating = clamp(0, 10, 5 + 2·Σ(wᵢ·cᵢ)/N)` with N = 50 fixed,
   `w = 4q̂(1 − q̂)`, the informative gate and its band from `informativeBand()`, why an empty slot scores
   neutral, the rank bands, a `w` table, and the Mock's defined `w = 1.0`.

Every numeral is rendered from the layer's own constants and functions, never retyped.

## 5. Deviations and objections (the spec was implemented; these are recorded, not fixed)

### 5.1 `lastDay` is the last RESOLUTION day, and a trigger clears it

G7's record has one date field and one count. Sealing needs *resolution* days, so `lastDay` has to belong
to `resolve()`; a `trigger()` that also wrote it would make the first resolution after a re-trigger land
on "the same day" and never count. `trigger()` therefore sets `lastDay = null` along with `resolved` and
`days`, and accepts (and ignores) an `opts.day` for symmetry. Nothing in the layer reads a trigger date.

### 5.2 A re-trigger zeroes `resolved` and `days` — that is the machine form of the rule

G2 says sealed is "3 clean resolutions across 3 distinct days **with zero re-triggers in that window**".
With a count-plus-a-date record, the only way to express "the window broke" is to restart the count. The
lifetime `triggered` survives, because `tellFor` ranks by it.

### 5.3 A sealed tag never re-opens

G2: sealing "retires it from the tell pool for good". So a trigger on a sealed tag increments `triggered`
and changes nothing else — `cleared` stays true, `sealed` stays true, the tell stays 1.00. If the intent
was that a sealed fault can come back, this is the line to change and it is one branch in `trigger()`.

### 5.4 `tellFor` takes the card index the caller already holds

"From `save.errors` alone" is honoured in the sense that matters: the *evidence* is the error log the
graders write, and no card gains a `tag:` entry. But an error line records `item` / `template` /
`forCard`, not a skill, so naming the make needs an id→skills lookup. `js/job/index.js` does **not**
import `data/cards.js` (236 KB) or `data/templates.js` (which pulls the whole generator graph), because
`#/stats` and the Settings panels have no use for either; the caller passes the index, exactly as
notes/J2.md §"qHatFor needs a card index" established for `q̂`. `js/job/board.js` already imports `byId`,
so the board pays nothing for this. With no index the answer is `null` with `source: 'no-index'` — a
forgotten `opts.cards` is diagnosable rather than silently indistinguishable from an empty log.

### 5.5 The record `tellFor` returns carries the PER-MAKE trigger count

`econ.tellFor` pays 1.25 only when `triggered > 0`. The index record's `triggered` is moved by
`index.trigger()`, which the job state machine calls; the *tell* is counted out of `save.errors`. If the
returned record carried the index's count, a fault the graders have logged but nothing has yet
`trigger()`ed would price at 1.00 and the envelope would print a tell it does not pay. So the record is
the index record with `triggered = max(index count, per-make count from the log)` — the triple
`{triggered, cleared, sealed}` J5 feeds to `econ.tellFor` is then exactly the truth about that make.

### 5.6 `CALL_DISAGREEMENT_BANDS[0]` in `data/job.js` is still swapped, and G3.1's prose is wrong about it

notes/J2.md §5.2 asked J1 for a one-line correction that has not been made: the constant says
`{from: 0.775, to: 7/9, money: 85, rank: 70}`, and the computed truth is `money: 70, rank: 85`. Settings
renders `call.disagreementBands()`, which is correct, and prints "the money says call 70, the rating says
call 85". **That also makes G3.1's sentence "money prefers the bolder call and rank prefers the honest
one" false for the first band** — in `q ∈ [0.775, 0.778)` the money prefers the *timider* call. The
second band matches the prose. I have implemented the arithmetic and not the sentence.

### 5.7 The push/bag threshold is printed in the "payout ladder" panel

G7 names exactly five panels, and `q*` — a probability the app prints before every bag-or-push, and on the
vault line — belongs to none of the five titles. It is printed at the end of "How the payout ladder
works", beside `m_chain` and the fee, which is where its variables already live. Likewise the Elo
expectation and the vault-grade bands close "How the Guard draws", because the House is that panel's
subject (G3.5 drives the vault grade from `R_player`). Five panels, every probability covered.

### 5.8 `crew-held` cannot know "non-idle at board time" from the save

G7's wording is "every wing has a manned, **non-idle** crew mark at board time". Idle is a per-*target*
property (`crew.isIdleFor(save, make, target)` — a make stands down only on its own due review), and a
trophy predicate is a pure function of the save with no target and no board. The shipped predicate is
"every wing has a manned make", with `progress = wings covered / 4`. If the idle clause is load-bearing,
it needs a board in `ctx` and that is a `js/trophies.js` change (§7 Requests).

### 5.9 The six trophies use existing groups

`tests/trophies.test.mjs:117` asserts every trophy's group is one of the six shipped ids. A seventh
`game` group would fail a test this ticket does not own, so `crew-held` / `index-25` / `index-68` are
`craft` and `chain-8` / `calibrated` / `clean-getaway` are `runs` (next to `night-owl-no`, which the Night
Before also pays).

### 5.10 `index-25` / `index-68` count SEALED cells, not resolved ones

G7 names them only by number. G2's certificate reads "here are the sixty-eight mistakes I no longer
make", and the thing that is finite and earned is the seal, so both milestones count seals. A save with 30
merely-resolved tags earns neither, and the suite pins that.

### 5.11 Two inline style declarations in Settings, and no CSS file touched

`.set-formula` is authored `white-space: normal` so a one-line formula wraps with a hanging indent on a
phone. The water-filling pseudo-code and the two two-line formulas need their own line breaks, so they
render as `pre.set-formula.mono` with `white-space: pre-wrap` and `text-indent: 0` set inline. That is a
DOM attribute in a file I own; `css/screens.css` belongs to J12 and was not touched (§7 Requests).

### 5.12 `settings.game` needs no `store.js` change

`fresh()` does not declare it and `fillDefaults` preserves unknown `settings` keys, so **absent means
on** — which is the reading G7 already gives `plan.js` (`settings.game !== false`). The toggle writes an
explicit boolean. Verified in the browser: toggling off persists `settings.game === false` and the app
reads it on the next paint.

## 6. Open issues

1. **Nothing calls `trigger()` / `resolve()` / `mint()` yet.** The miss path and the day-roll belong to the
   job state machine and to `plan.js`/`home.js`, which this ticket does not own. Until they are wired, the
   Fault Index panel shows every cell as untouched on a real save, and the *tell* still works, because it

2. **`js/job/state.js` appeared in the tree at 04:12 from another lane** while this ticket was running. I
   did not read or touch it; if it has already implemented Backcheck spend/mint, one of the two should be
   deleted and the other imported. Mine is the DOM-free, pure one and has 18 tests on it.
3. **The Fault Index renders as a list, not a grid.** 68 cells in 11 groups, styled with the shipped
   `.st-pattern` card. It is legible at 375 px and at 1280 px with no overflow, but "68 cells" reads as a
   grid in the spec, and a grid needs a CSS block that is J12's.
4. **The six game trophies are visible with the layer off.** They print their condition like every other
   unearned tile and can never fill while `save.game` is frozen, which is honest but slightly odd. Hiding
   them would mean `data/trophies.js` reading `settings.game`, which makes a predicate depend on a
   setting; I would rather Stats filter the tiles, and that is a one-line change I can make on request.
5. **`tellDetail` is O(errors × tags-per-error) per make**, so `tellsFor` is 19 passes over the log. The
   log is capped at 300 entries (`CAPS.errors`), so the worst case is ~5 700 attributions — under a
   millisecond in the harness, but if the board calls it per envelope it should memoise one
   `tellsFor(save, {cards: byId})` per job rather than 10 `tellFor` calls.
6. **`indexProgress` is recomputed on every Stats render.** 68 record reads; negligible, but it and
   `areaRollup` both walk the catalogue and could share one pass if this ever shows up.

## 7. Requests for other file owners

**J5 / J6 (`js/job/board.js`, `js/screens/job.js`) — pass the index you already hold.**

The record returned carries `{triggered, cleared, sealed}`, which `econ.tellFor` reads directly, plus

`index.tellsFor(save, { cards: byId })` per job over 10 per-envelope calls (§6.5). For generated targets
also pass `templates` from `data/templates.js` if the screen already has it; without it a `T-…#seed`

**The job state machine (whoever owns `js/job/state.js`) — four hooks, all pure, all one line.**
- on a miss, for every tag the grader returned: `save = index.trigger(save, tag).save;`
