## 1. What was built

### 1.1 `site/js/plan.js` — the week, in one place

G7's table says "`site/js/plan.js` | `nextAction` gains one branch". **`nextAction` is not in
`plan.js` — it is `page.js:455`**, and `page.js` may not import `plan.js` because `plan.js` already
imports `page.js` (the edge would be a module cycle). So, by the ruling G10 makes twice elsewhere
(**the code wins**), the branch is implemented here as a pure decorator over whatever
`page.nextAction` returned, and `screens/home.js` — the one screen that paints the primary button —
applies it. The request for the one-line hook inside `page.nextAction` is in §6.

The gate, in precedence order, is `boardPolicy()`:

| # | rule | kind | posts |
|---|---|---|---|
| 1 | `settings.game === false` | `off` | — |
| 2 | local hour ≥ 22 | `closed` | **nothing** |
| 3 | no test date / post-test | `nodate` · `post` | nothing |
| 4 | D = 0 | `morning` | a board with **no stakes, no calls**, and `Go.` |
| 5 | D = 1 | `night` | **nothing**; `href = '#/run/night'` |
| 6 | D = 2 | `review` | the REVIEW BOARD: `...REVIEW_BOARD` verbatim |
| 7 | Mon–Fri 07:00 ≤ t < 14:15 | `school` | the **RUN** shape only |
| 8 | D ≥ 3 | `job` | the ordinary board; `shape: null` defers to `job/board.js shapeFor` |

Rules 6 and 7 compose: inside the school window at D = 2 the board is the REVIEW BOARD **at the RUN
shape**. Every no-board state still names a study route — `#/run/night`, `#/run/morning`, `#/today` —
so G9 #9's "none of it locks a single study door" holds by construction.

`refuseFor(shape)` is the 22:00 refusal and it is **computed**: the shape's own projected wall clock
(`PUBLISHED.shapeTable` / `econ.shapeTable`) added to `now`, compared with **today's 22:00**, with the
RUN's real end time on the alternative. The four shapes therefore flip at four different clock times
(asserted), which is the property no fixed constant can have. G12 #40e's case is pinned: a VAULT
started at 21:30 ends at 21:47 and is **not** refused.

`jobBoundary(save, { now })` is the trigger the job screen calls at each target boundary: a bound
COMMIT first, then the 22:00 close, both at FULL value. It is policy only — the arithmetic stays in
`job/state.js` (`commitFire` / `quietClose`), so there is exactly one of it.

`payCleanGetaway(save)` is G5's "the game paying the player to stop playing it": completing the Night
Before stamps `player.records.cleanGetaway` once and mints one Backcheck. Home calls it the first time
it sees a finished Night Before.

### 1.2 `site/js/screens/home.js` — TONIGHT'S BOARD, two passes

**Pass 1 is static** and is a real, readable board — not a loading state. It has no spinner, no
`aria-busy`, and it comes entirely from `store` + `schedule.dueList` + `save.game.log` +
`data/job.js`:

* the week state and its line (`No board tonight · …`, `Board closed · …`, `Go.`, the REVIEW BOARD
  heading, the school-window line);
* the contract row frame — `postedCountEstimate(dues + shape.targets)` rows, lettered A–E, inside an
  `<ol>` whose `min-height` reserves `BOARD.postedMax` rows, so a thin board in pass 2 moves nothing
  below it;
* the four wing labels of the supply list;
* `~N min`, `ends HH:MM` and the projected split — the split from the student's **own** last five
  jobs when `save.game.log` has them (`~60 % game · your last 5 jobs`) and from the shipped table
  otherwise (`~43 % game · projected`), exactly as G1 statement 1 requires;
* the cold-crew strip with its **dues** count, which `dueList` knows.

**Pass 2** (`fillBoard`) runs after `job/board.js` resolves and writes ink into the nodes pass 1 already
sized: contract label, lock count, cold days, posted, wing, per-wing supply numerals, the idle-crew
count and its minutes, the corrected `~N min` / `ends` / projection, and — last — the primary button's
own line, so the CTA and the panel print the **same** wall clock.

Every pass-2 numeral is a `numeral(cls, chars)` node: `display:inline-block`, `min-width: <chars>ch`,
`data-pending="1"`, `.muted`, filled with `·` characters. `setNumeral()` swaps the text and drops both
markers. Pass 2 never calls `replaceChildren` or touches `innerHTML` on a row, so it cannot change
geometry.

Measured in chromium at 375×667 on a seeded save (`/tmp/.../j11-check.mjs`): pass 1 renders, pass 2
completes with `data-pass="2"` and **`[data-pending]` count 0**, **zero console errors**, and the CTA
reads `JOB · 11 targets · ~16 min · ends 05:34 · 37 % game` against the panel's
`JOB · ~16 min · ends 05:34 · ~37 % game · projected`.

### 1.3 `site/js/screens/mock.js` — the big score keeps its one call

No call row, no stake, no crew, no chain, no guard, no envelope — asserted by scanning every `h('…')`
selector the screen builds (89 of them) for those words, and by asserting the file imports none of
`job/crew.js`, `job/econ.js`, `job/guard.js`, `job/state.js`, `job/board.js`, `job/index.js`. The one
import it does take is `job/call.js`, which is pure arithmetic.

`mockCall(run)` scores the **existing** prediction slider and `applyMockCall(save, run)` pushes it into
`player.rating.calls` at `w = 1.0` with `skill: null`, then refreshes `rating.value`, `rating.n` and
`player.rank`. `submitRun` calls it once, after `applyMisses`. A `retry` earns none (as it earns no XP
and no PB); `settings.game === false` earns none; a run that already carries `run.call` is not counted
twice.

### 1.4 `site/js/screens/boss.js` — the vault is a frame, not a variant

`#/boss/B2?job=1` sets `opts.vault`, which reaches exactly **three lines**: the local flag, the root's
`data-vault`, and the back arrow's href (`#/run/job` instead of `#/today`). The suite asserts those
three lines by matching each one, and asserts that `finish()`, `recordBossRun()`, `checkQuestion()`,
`loseHeart()` and `drawHearts()` contain no mention of it. `HEARTS === 3`, `CONTINUE_HEARTS === 1`,
the KO copy and the `onFinish(record)` hook (which already existed — J6 reads the record through it)
are byte-identical.

## 5. Deviations and objections (the spec was implemented; these are recorded, not fixed)

### 5.1 `nextAction` lives in `page.js`, not `plan.js` — the branch is a decorator

G7 names `plan.js nextAction`. The function is `page.js:455`. `page.js` cannot import `plan.js`
(cycle), and I do not own `page.js`. The branch is therefore `plan.nextActionFor(save, act, opts)`,
applied by `screens/home.js`. Behaviourally identical for the one screen that paints the button;
`screens/run.js:1239` also calls `nextAction` (for the Page Summary's "Next:" line) and will keep
printing the **study** action until the one-line hook in §6 lands. That is the only place the two
differ, and the Summary is J6b's screen.

### 5.2 Home carries a second copy of the week gate, pinned equal

`home-r2.test.mjs:147` forbids a static `plan.js` import in Home and `job-index.test.mjs:637` forbids a
static `../job/*` one. Both tests win (G10 #21). Pass 1 has to decide *whether a board posts at all*
before either module is loaded, so `home.weekGate` / `home.modeStatic` re-state the rule over the same
`data/job.js WEEK` constants, and the suite pins them to `plan.boardPolicy` / `plan.modeFor` over 160
states. This is the device `plan.qFor` / `page.qFor` already use in this tree. **If a third copy is
ever needed, the right fix is a new DOM-free `site/js/job/week.js` that both import — I did not create
one because it is not a file this ticket owns.**

### 5.3 Pass 1 cannot print contract labels, wings, lock counts or per-wing supply numerals

G7 lists them as pass-1 content ("derivable from `save.cards` and `dueList`"). They are not: a card
record carries no skill, so **card → make → wing needs `data/cards.js` (233 KB)**, which is exactly the
static import home-r2 exists to prevent. They are pass-2 numerals occupying their final width in pass
1, which is what J13's real criterion — no layout shift, no spinner — asks for. The wing *labels* of
the supply list, the row frame, `~N min`, the end time and the projected split **are** pass 1, as
specified.

### 5.4 `REVIEW_SHAPE` is the constant `'JOB'`

D = 2 must not post a VAULT, so the week has to name a shape rather than defer to `board.shapeFor`
(which returns `VAULT` whenever `bossReady` fires). I first made it `qFor`-dependent (`JOB12` on a
heavy plan); that made §5.2's pin impossible, because Home cannot call `qFor`. It is now the constant
`JOB`: the Final Sweep already makes every bucket ≤ 2 item due, and JOB12 on top of that leaves
COMPOSED S1's 10–25 minute session (JOB12 full-use is 20:56 *before* the sweep). **Objection recorded:**
the spec does not name the REVIEW BOARD's shape, so this is a choice, not a transcription.

### 5.5 `~N min` on the board is the WALL clock, not the answer minutes

`job/board.js`'s `COPY.primary(...)` is called with `Math.round(recommend.minutes)` — the drafted
**answer** minutes (7.0 for a JOB-10) — beside `ends HH:MM`, which is `now + answerS + gameS`. The two
disagree by the whole game half: `~7 min · ends 20:31` is not a possible pair. G5 requires the primary
button to print "cards, minutes and the wall-clock time the run ends", so both of my surfaces print
`Math.ceil(wallS / 60)`, and `primaryLineFor(board)` reprints the CTA from the board's own
`endsAt − now` after pass 2. Request filed in §6.

### 5.6 The Mock's prediction is continuous; `call.credit` takes a binary outcome

`credit(p, ok)` computes `10 − 40(p − o)²` with `o = ok ? 1 : 0`. A Mock's outcome is the realised
score fraction, which is not binary, and `player.rating.calls[]` stores `{p, ok}` and recomputes the
credit on every read. The entry therefore stores the **error-equivalent** call `p' = 1 − |p − o|` with
`ok = true`, for which `credit(p', true) === 10 − 40(p − o)²` **exactly** — so the window needs no
special case, `ratingFrom` needs no branch, and the quadratic score stays strictly proper (asserted by
grid search). The raw `pred` and `score` stay on the run, and `calibration(run)` still prints them.
**Objection:** a reader of `player.rating.calls` sees `{p: 0.93, ok: true, skill: null}` for
"predicted 88, scored 81". The clean fix is a continuous `call.creditC(p, o)` — request in §6.

### 5.7 The Clean Getaway's mint is re-stated in `plan.js`

`state.mintBackcheck`'s free-mint branch is gated on `reason === 'vault'`, and the Night Before is a
third source. `plan.js` must also stay off the job machine's static graph (`onboard.js` and `night.js`
import it eagerly). So `payCleanGetaway` does the six lines itself, takes an injectable `mint`, and the
suite asserts the two produce byte-identical `game.backchecks` at held 0/1/2/3. Request in §6.

### 5.8 No CSS was added

`css/job.css` and the `/* === G-job === */` block in `screens.css` belong to J6 / J12. The panel is
therefore styled by the existing `.card` / `.mono` / `.muted` / `.fs-1` classes plus four inline
declarations (`min-width` on the numerals, `min-height` + `list-style: none` on the two lists). At
375 px a contract row currently wraps to two lines, which is why `BOARD_ROW_PX` is 40 and not 24.
Request in §6.

### 5.9 The job primary is route-guarded

Until `run.js` had a `job` KIND_META entry, `#/run/job` rendered "No such run". `boardMods()` therefore
reads `run.kindMeta('job')` and Home keeps the study CTA as the primary while it is missing. The J6
lane's entry landed during this sitting, so the guard is now a no-op — it stays as a cheap safety net
and costs one property read.

### 5.10 Shapes and modes the week does not cover

`modeFor() === 'nodate'` (no test date) and `'post'` post no board, because G7's branch is explicitly
conditioned on `modeFor() === 'page'`. A student with no test date therefore sees the study tool with
no game layer at all. That is spec-literal and may not be intended — G5's table starts at D ≥ 3 and
never says what happens without a date.
