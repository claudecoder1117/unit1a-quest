# T06g — Misconception catalogue

Owner files: `site/data/misconceptions.js`, `tests/misconceptions.test.mjs`, `notes/T06g.md`.
Spec: COMPOSED S8 #6g, S3 (tags per grader), S4 Patterns panel, S7 cheat sheet ("most-missed … per area").

## What was built

`site/data/misconceptions.js` — the ONE place every misconception tag is named. 67 tags, each
`{ title, fix, area }`:
- `title` ≤ 40 chars, a label for the Patterns panel / error log ("Gave the complement").
- `fix` ONE student-facing line ≤ 140 chars, what to do next time, never an item number or an
  answer ("You found the complement — reread what the question asks for and write that expression first (180 − x for a supplement).").
- `area` grouping id from `AREAS` (comp-supp · setup · ratio · roots · factoring · figure ·
  notation · vocab · classify · reasoning · general) — lets `data/sheet.js` (T14) pick the
  most-missed tag per area and `stats.js` (T11) group the Patterns panel.

Every entry and the map itself are frozen. Keys are kebab-case. Never rename a key a save may
already carry (`save.errors[].tags`); `lookup()` degrades gracefully for unknown ones.

`tests/misconceptions.test.mjs` — 11 tests: catalogue integrity (shape, bounds, one-line, no
placeholders, no duplicate key literals, every S3/ticket tag present); a **static scan** of
`site/js` and `site/data` that fails on any emitted tag literal missing from the catalogue; and the
helper API. The scan tolerates directories/files that do not exist yet (an empty scaffold is green).

Naming guide for grader/generator authors: `gave-<intermediate>` for a `num` distractor hit
(`angle`, `complement`, `supplement`, `smaller`, `larger`); `used-90-for-supp` / `used-180-for-comp`
for the wrong constant; `stopped-early` for an unfinished `asks` chain; `sign-flip` for `v == −ans`
on a `num` part (`sign-whole` is the **factored** grader's whole-expression negation); the factored
grader's `almost` for a GCF left inside a bracket is `gcf-incomplete`, the `ctx.strictGCF` `wrong`
is `missing-gcf-strict`.

## Exported API (`site/data/misconceptions.js`, ES module, DOM-free, imports nothing)

```js
export const MISCONCEPTIONS            // frozen { [tag]: { title, fix, area } }  — also the default export
export default MISCONCEPTIONS
export const AREAS                     // frozen [{ id, label }] in display order; includes 'general'
export const TAGS                      // frozen string[] — Object.keys(MISCONCEPTIONS) in catalogue order
export function isKnownTag(tag)        // → boolean; never throws (non-strings, prototype keys → false)
export function lookup(tag)            // → { tag, title, fix, area, known }
                                       //   unknown → { title: tag with dashes → spaces, fix: generic line, area:'general', known:false }
export function patternLine(tag, n)    // → `${tag} ×${n} — ${fix}`   (S4 Patterns line; n coerced to int ≥ 0)
export function groupByArea(counts)    // counts: { [tag]: number } → [{ id, label, tags:[{ tag, count, title, fix }] }]
                                       //   AREAS order, empty areas omitted, count desc then catalogue order,
                                       //   non-positive/NaN counts dropped, unknown tags land in 'general'
```

Consumers: `js/screens/stats.js` (T11 Patterns panel: tally `save.errors[].tags` → `groupByArea` →
`patternLine`), `data/sheet.js` (T14: top tag per area → the personalised lines), the card screen's
misconception line (`lookup(tag).fix` is a valid fallback when a card's `msg` is absent),
`tests/coverage.test.mjs` (T06f: import `isKnownTag`/`TAGS` for its "every emitted tag exists" check
— or simply rely on this test, which already enforces it).

## How the scan works (what graders/generators must do)

`tests/misconceptions.test.mjs` walks `site/js/**/*.{js,mjs}` and `site/data/**/*.{js,mjs}` (the
catalogue itself excluded) and extracts every literal of these forms, including inside comments:

```
tag:'x'   tag: "x"   tag:`x`   tag = 'x'   tags:['x', "y"]   tags: [ 'x',\n 'y' ]   tags.push('x', "y")
```

Non-literal entries (`tags:[t]`, `tags.push(dyn)`, `{tag: t} = r`) are ignored. A grader that
builds a tag dynamically (`'gave-' + name`) must declare the possible values in a comment, e.g.
`// tags:['gave-angle','gave-complement','gave-supplement','gave-smaller','gave-larger']`, so the
scan covers them. Failure output lists `file:line  tag  (nearest: …)` with the three closest
catalogued tags.

## Open issues

1. **`node --test tests/` (the BUILD-POLICY §3 / `package.json` `npm test` / pages.yml form) does not
   work on the installed Node 26.3.0.** Node ≥ 21 treats positional args as globs; on 26.3.0 the
   pattern `tests/` matches the *directory* and the runner tries to execute it as a test file:
   `Error: Cannot find module '…/unit1a-quest/tests'` → 1 fail, 0 tests run. Reproduced on an empty
   scratch scaffold with a trivially passing test, so it is environmental, not caused by any ticket.
   Working forms: `node --test` (bare) and `node --test 'tests/**/*.test.mjs'`. Node 20 (the CI
   floor in S6) expands directories, so the Action may pass while local runs fail — or vice versa.
   Only Node 26 is installed here (`/opt/homebrew/opt/node@26`).
2. Tags are a superset of what S3 names: 67 vs the 11 literally listed. Unused entries cost nothing
   (the scan only fails on *missing* tags). If a grader author needs a tag not here, they cannot edit
   this file — they write a Request in their note and use the closest existing tag meanwhile.
