## How a run is composed (S2 + S4)

`composeBoss(bossId, seed, T)` → six slots, deterministic in `(bossId, seed)`:

1. **An explicit `pool` wins** (only B7). Its `2 + 2 + 2` is trimmed to the five Variant slots by dropping
   one from a group that still has ≥ 2 — so B7 is always `{2,2,1}` over `T-seg-mid` / `T-quad-ctx` /
   `T-factor-a2`, never six midpoint problems (S2's own reason for the mixed pool).
2. **`extra` asks are placed first** and count against the five (B2's "+ 1 pairs ask").
3. Otherwise candidates are **the boss's own modules' templates**. Every boss skill that has such a
   template is covered once (preferring a template whose *primary* skill it is), then the remaining slots
   go to the least-used candidate of **tier ≥ 2**.
4. A module with **no generator at all** (M9) falls back to its **Original Set**, elite excluded — that is
   how B2 gets four `asn-*`/`qz-*` cards.
5. The five are sorted by tier ascending (a boss never opens on its hardest item), then the **elite
   original** is appended as slot 6.

What that produces at attempt 1 (`node --test tests/boss.test.mjs` pins the invariants, not the exact draw):

Item seeds are `"<runSeed>#<n>"` (and `"<runSeed>#elite"`), so RETRY SAME SEED replays the identical six
problems and the sort order can change without changing which problems you get.

## The rules, and where each one lives

- **3 hearts, one submit = one heart.** `bus 'card:wrong'` fires once per *charged* submit (T09 grades one
  entry per submit, and a multi-field `multi` is one entry) — so a multi-part item costs −1 per submit,
  not per part, exactly as S4 says. `almost` / `malformed` never emit it, so they are free here too.
- **No hints.** `mode:'boss'` hides T09's ladder.
- **B4's equation slot is required.** `prepareItem()` forces `optional:false` on it (the widget also drops
  its "Skip setup" button because `ctx.boss` is set); **every other boss removes the optional setup part
  from its items**, since S3 makes the slot required in B4 and optional *only on Cards*. A wrong setup in
  B4 sets `setupMiss` — no heart, no flawless, no +300 — and is announced as such at the moment of the miss.
- **A miss names the skill in words** (S4). A catalogued misconception tag speaks when the grader returned
  one; otherwise `SKILL_MISS[skill]` — one sentence per skill, all 19 present — plus a
  `Drill 5: <skill name>` button pointing at `#/run/drill/<SKILL>` (T16's route).
- **A Boss miss on a Mastered skill drops `m` to 69** (S4). Mastered-ness is snapshotted before the item
  is graded, because the Card engine's own first-wrong EMA has already moved `m` by the time we see it;
  `applyBossMiss` only ever lowers (if the EMA landed below 69, the harsher number stands).
- **CONTINUE?** at 0 hearts: the item's worked solution plus a **one-tap check question about it** — "which
  line is the FIRST move in the solution you just read?", three options drawn from the solution's own
  steps (a wrong tap strikes that option out and you pick again; the hint ladder's H1 is the fallback for a
  short solution). Pass → 1 heart back, run flagged `*`, the killed item is booked as a miss, next item.
  Decline → **knocked out**: the run record is written with `won:false`, so `boss:{id}` is not earned,
  while every XP point, mastery update and tile the items already wrote stays.
- **The combo is never touched** (S4 "Boss and Mock never touch the combo"). T09's engine still moves
  `session.combo`; this screen snapshots it on mount and restores it after every card event.
- **No clock** (S9 #6). Time is recorded and only shown afterwards: per-item times in the result table and,
  on a same-seed re-run, the ghost split per item (green/red, a gold "best split" flash).
- **PB** = fastest **won, unflagged** run on that seed. A `*` run and a KO never write one and are never
  the ghost. **Boss XP once per seed**: `+150` (`+300` more when flawless), and a second win on the same
  seed pays 0 and says so.
- **Autosave** (S6): `save.inProgress = {kind:'boss:B4', seed, idx, hearts, flagged, setupMiss, items, stash}`
  on every item boundary, every 5 s, and on `visibilitychange`. A Page that was in progress is **stashed**
  inside that record and put back when the boss ends, so starting a boss mid-Page does not eat the Page.
  Re-entering `#/boss/B4` offers `RESUME · item 3 of 6` with the hearts you had left.

## Exported API


## Decisions worth knowing

- **Non-B4 bosses drop the optional setup part** rather than showing a box that cannot be skipped and does
  not have to be answered. T09's `isSetupSlot()` only treats an equation part as skippable in
  `mode:'card'`, and the generated parts already carry `optional:true`, so in a boss the part would
  otherwise sit there un-skippable *and* ignorable. S3 gives the slot to B4 only; this makes that literal.
- **Won = you reached the end of the queue with a heart left.** Hearts are the win condition, so a run that
  missed an item (each miss cost hearts) can still be a win. Taking CONTINUE on the **elite** therefore
  also ends as a win — flagged `*`, no flawless, no PB, no +300. The alternative (a KO for a CONTINUE on
  the last item) would make the last heart mean something different from the others.
- **XP once per seed is absolute**: a second win on a seed pays 0 even if it is the first *flawless* one.
  The trophy `boss-flawless:{id}` is still earned (it reads the run record, not the XP), which is the part
  that is actually about the achievement.
- **The tier floor is dropped when a module has nothing above tier 1.** S4 says "5 Variants (tier 2–4, all
  skills of the boss)"; B1's VOC and CLASS only have tier-1 generators, and covering the skill is the more
  load-bearing half of that sentence. It only affects B1.
- **B2's five are four M9 originals + one pairs Variant.** M9 has no generator at all, so "5 Variants" is
  unbuildable there; the Original Set is what the module is.
- **The check question is content, not a formality**: its options are the solution's own step lines, so it
  cannot be answered without reading. A wrong tap strikes that option out instead of ending the run —
  the gate is attention, not a second punishment.
- **`applyBossMiss` only lowers.** See above.
- **The stash.** `save.inProgress` is a single slot (S6) and a Page lives there too; a boss stashes the
  Page inside its own record and restores it on finish, so the two features cannot eat each other.

## Open issues

1. **A blank B4 setup cannot be "skipped" on purpose.** S3 says "a wrong or blank setup costs no heart but
   forfeits flawless", and here the slot is required: a blank submit is `malformed` (free, no progress), so
   the only way past it without an answer is three deliberate wrongs, which reveals the whole item (the
   Card engine's third-miss path) and books it as a miss — still no heart lost. If Oliver wants a literal
   "leave it blank and move on", T09 needs one line: honour `part.optional === true` in `mode:'boss'` for
   the *entry* while keeping the widget's Skip button hidden, or expose `showSolution()` on the view.
2. **T09's auto-H1 fires invisibly in a boss.** `chargeWrong()` calls `revealHint(0, {auto:true})` on the
   second wrong of a part without checking `hintWrap.hidden`, so a boss item silently records `hints:1`.
   It changes nothing that is scored (with `firstTry:false` the XP quality, rarity and mastery score are
   already decided by the attempt), but `cards[id].hintsUsed` is wrong by one. One-line fix in card.js —
   see Requests.
3. **`setupMiss` is only persisted by the next autosave tick** (≤ 5 s) — `writeProgress()` runs on item
   boundaries and the 5 s timer, not on every wrong. A reload inside that window forgives a setup miss.
4. **No par line per item on the result screen.** Each item's own result strip already shows `you vs par`
   (T09) as it finishes; the boss table shows time and split only.
5. **B5 is five tier-4 bisector strips.** M7 has only `T-fig-bisect-L/Q`, both tier 4, so The Bisector is
   the longest boss by a distance. Nothing in the spec allows a lighter pool; worth watching in play.
6. The result screen is not re-openable: leaving it drops the run summary (the run itself is in
   `save.runs`, and `#/stats` shows per-boss bests and splits — T11 already reads the record shape).
