## What was built

### `data/skills.js` — the 19-skill graph (S1, verbatim)
Ids, UI names, weights (sum 100) and prereqs exactly as the S1 table. Prereqs are recommendations (never locks).
FIG-ALG's "tier-4 items also need QUAD-SOLVE" is item-level (`needs:[…]` on ang-10, T06b), not a prereq.

### `data/modules.js` — M1–M13, the 7 Bosses, the 4 family tiles (S2, S4)
- Every SOURCE id lives in exactly one module's `originals` (197 ids, no duplicates), in sheet order.
  M4 additionally carries `rooms` (Grotto / Nested / Ratio) as sub-groups of the same set.
- `bosses`: B1 Definitions Gauntlet (M1+M3, elite `not-04`) · B2 The Oracle (M9 + 1 pairs ask, `asn-32`) ·
  B3 Kuta's Revenge (M10+M11+M12, `fac-16`, prompt needs M11/M12 tiles ≥ Bronze) · B4 Sixteen (M4+M5,
  `wp-16`, `equationRequired:true`) · B5 The Bisector (M7, `ang-05`) · B6 Crossroads (M6+M12, `ang-10`) ·
  B7 The Triangle (M8, `ang-04`, mixed `pool` of T-seg-mid / T-quad-ctx / T-factor-a2 × 2 each).
- `families`: fam-quad-a1, fam-quad-a2, fam-quad-ctx (M11), fam-sys (M12) with template + sheet ALG.

### `data/sheets.js` — the 12 Binder tabs (S1 order)
VOC · AP-1 · AP-2 · AP-3 · AP-4 · DOC · WP · ASN · QZ · FAC · ALG · BONUS, each with display `name`, the page it
came from, and `ids` in sheet order. `BONUS` is a new tab id (S1 had none; S2 says bonus-* "sit under the
Bonus tab") — T06d already uses `sheet:'BONUS'` on bonus-* cards, so the two agree. The VOC tab order is
S2's M1 order: voc-01..23, not-01..09, def-01..14, fact-01..05, cls-01..04.

### `data/vocab.js` — the 23 §0 terms
Per term: `id`, `key` (slug), `term`, `def` (VERBATIM from SOURCE.md §0 — checked programmatically; `side` and
`vertex` are `derived:true` because §0 defines them only inside the angle bullet), `ask` (the definition as
shown when the student must produce the term — equals `def` except for line / plane / complement / supplement,
whose verbatim text contains the term), `aliases` (accepted typed forms incl. common misspellings),
`group` + `confusable` (≥ 3 keys; S2's four seed groups complement/supplement · ray/segment ·
adjacent/linear pair · collinear/coplanar plus point/line/plane · angle/side/vertex · the four angle types),
`example` (mini-markup, every measure true of figure F1), `hints[3]`, `note`, `symbol`.
Also `termmatchSets` — four 6↔6 sets covering all 23 terms (angle bisector repeats).

### `data/cards/m1.js` — the 55 M1 cards (sheet order)
| ids | skill | tier / par | parts |
|---|---|---|---|
| voc-01..23 | VOC | 1 / 20 | `pick:'one'` over **mc** (term → definition, 3 confusable-group distractors) · **term** (definition → type the term) · **termmatch** (its 6↔6 set, `blitz:false`) |
| not-01, 02, 07, 08, 09 | NOTE | 1 / 20 | **mc** of rendered symbols: line ↔ · segment ¯ · m∠ vs ∠ · ≅ vs = · plane naming |
| not-03, 04, 05, 06 | NOTE | 2 / 45 | **notation** builder on F1: length trap (no bar) · ray endpoint-first trap (B1 elite, `ray-order`) · opposite ray · ∠ with vertex in the middle |
| def-01..14 | VOC | 1 / 20–40 | **cloze** with 4-chip rows; text is the §0 definition verbatim with 1–3 blanks (one per §0 bullet) |
| fact-01..05 | ASN-PLP | 1 / 30–40 | `pick:'one'` over **cloze** (verbatim §0) · **asn** verdict form (`mock:true`, reason + 2 distractors) — fact-04/05 are the two "exactly one" postulates |
| cls-01..04 | CLASS | 1 / 20 | **classify** on F1: 31° acute · ⊥ right · 121° obtuse · straight (A-F-D) |

Every card: `id, module:'M1', sheet:'VOC', src, srcFile, tier, par, skills[], needs:[], stem, figure|null,
parts[], hints[3] (H1 relationship → H2 discriminator → H3 one step from the end, never the answer),
solution[] ({say, math}), misconceptions[], verified:true`. No `teacherKey`/`orig` (BUILD-POLICY §1).
Figure cards reference `figure:{id:'F1', rename:{}, labels:[…], notToScale:false}` (T04's fan model:
∠CFD 31°, ∠BFC 59°, ∠BFD 90°, ∠AFE 31°, ∠BFE 121°, ∠AFC 149°, ∠AFD 180° — every number in the cards is checked
against those ray angles). cls-02 says "{ray FB} ⊥ {line AD}" rather than naming which side the square is drawn on
(T00 found the scan's mark is between FB and FA; ∠BFD = 90° either way).

**Every wrong option teaches in one line (S9 #4)**, in both places the engine can read it, generated from one
table per card so they cannot drift:
- on the part, through the grader's own hook: mc `distractors:[{text, why, term?, tag?}]`, term
  `confusables:[{term, msg}]`, cloze `blanks[i].why:{[chip]: msg}`;
- on the card, `misconceptions:[{part, answer, tag?, msg}]` for the error log / Patterns panel.
Only catalogued T06g tags are used (19 of them: confused-ray-segment, confused-comp-supp,
confused-collinear-coplanar, confused-adjacent-linear, confused-vertical-linear, misclassified, line-vs-segment,
segment-vs-ray, bar-on-length, wrong-decoration, ray-order, vertex-not-middle, m-vs-angle, congruent-vs-equal,
plane-naming, used-180-for-comp, used-90-for-supp, boundary-90, boundary-180). Where the catalogue has no pattern
(point/line/plane, angle/side/vertex, bisector, intersection facts) the misconception carries **no `tag` key**
— the message still shows; see Requests → T06g.

### `pick:'one'` (design decision, please honour — T09/T16)
S4 makes vocab tier 1 with par 20 s, S7 sizes "12 M1 cards ≈ 3 min", and the plan weighs an M1 card at ⅙ of a
tier-3 card — so a voc/fact card must be ONE ~15 s ask, not three sequential parts. S2 lists term/mc/termmatch
as the three *presentations* of a term; I model them as `parts[]` plus card-level `pick:'one'`:
render exactly one part per sitting — `parts[history.length % parts.length]` (first sitting → mc, then the
harder recall `term`, then the 6↔6 `termmatch` on a review); HP pips = 1; graders untouched. If a consumer ignores
`pick` the card still works (it just asks all three). BLITZ must skip parts flagged `blitz:false` (termmatch).

## Exported API (all ES modules, DOM-free, no runtime deps, no Math.random)

```js

// data/vocab.js
```

### Part shapes used (all consumed successfully by the T05 graders — see round-trip below)
```js
{ id:'mc',    type:'mc', prompt, answer, distractors:[{ text, why, term?, tag? } ×3], term? }
{ id:'term',  type:'term', prompt, answers:[canonical, ...aliases], confusables:[{ term, msg } ×3] }
{ id:'match', type:'termmatch', prompt, set:'tm-2', pairs:[{ term, def } ×6], blitz:false }
{ id:'cloze', type:'cloze', text:'… [_] …', blanks:[{ answer, options:[4], why?:{ [chip]: msg } }] }
{ id:'build', type:'notation', prompt, kind:'len'|'ray'|'ang', pts:[…], letters:['A'…'F'] }
{ id:'cls',   type:'classify', prompt, measure:'31', answer:'acute', options:['acute','right','obtuse','straight'] }
{ id:'asn',   type:'asn', mock:true, statement, answer:'A'|'N', reason, distractors:[2] }   // fact-* only
```
Extras beyond S6 (`prompt` per part, `pick`, `blitz`, `mock`, `statement`, `set`, `letters`, `measure`,
`options`, `term`, `part` on misconceptions) are additive; every S6 field is present.

What the two scripts prove (all green at hand-off):
- 55 ids, unique, identical (and in the same order) to `sheets.js` VOC and `modules.js` M1; every card has
  skills/sheet/tier/par/stem/parts/hints[3]/solution; every `skills[]` entry exists in `skills.js`; skill per
  prefix = S2 manifest line (voc/def → VOC, not → NOTE, fact → ASN-PLP, cls → CLASS).
- Every vocab `def` (non-derived) and every cloze text with its answers filled in is a substring of
  SOURCE.md §0 (case-insensitive, trailing punctuation loose).
- Every mc option set is 4 unique texts; every cloze blank has 4 unique chips incl. the answer and `why` keys
  are wrong chips; every misconception is reachable (its `answer` is a live wrong option of its part) and its
  `tag`, when present, is catalogued.
- Round-trip through `site/js/grader/{mc,term,termmatch,cloze,notation,classify,asn}.js`: 106 parts, 300
  wrong-option probes — correct answers (text and index; aliases; upper-case/punctuated forms) → `correct`;
  every distractor / confusable / wrong chip / wrong bucket / wrong verdict → `wrong` **with the authored
  message and tag**; reversed letters accepted for len/ang and rejected with `ray-order` for rays; empty →
  `malformed`; asn: reason shown on Cards, hidden in Mock, chips only on a miss / Full 36; termmatch layout
  never leaves definitions in authored order; `mathfmt`/`stripMarkup` leave no stray braces anywhere.
- F1 claims: ∠CFD 31, ∠BFC 59, ∠BFD 90, ∠AFE 31, ∠BFE 121, ∠AFC 149, ∠AFD 180 recomputed from the ray angles.

Suite at hand-off: `node --test 'tests/**/*.test.mjs'` → **407 tests, 407 pass, 0 fail** (an earlier run showed 5
failures in T02/T03/T05 files — `strip.js` placeholder tag, `mc.js` no-random comment, numeric tolerance — all fixed

## Open issues

1. **`node --test tests/` fails on Node 26.3.0** (directory positional treated as a file) — environmental,
   reported by T00/T06d/T06g; use the glob form. Seconding the request to T01 to change `package.json` /
   `pages.yml` / BUILD-POLICY §3.
2. **def-10 / def-11 formula blank is numeric by necessity.** The cloze grader compares word blanks by
   `normalizeTerm` (letters only), so "90 − x" / "180 − x" / "x − 90" all normalise to "x" and could not be told
   apart. The text is therefore "Complement of x = [_] − x" with a numeric blank (90 vs 180 …) — the
   90-vs-180 confusion (`used-180-for-comp` / `used-90-for-supp`) is still the thing being tested.
3. **No figure-tap notation item** (S2 mentions "figure-tap 'the object matching segment BD'"). S3 defines no
   such part; the builder's letter taps cover the figure interaction. Add later as a `notation` variant if T08d
   grows a tap-the-object mode.
4. Misconceptions without a catalogued pattern carry no `tag` (see Requests → T06g). If T06f's coverage test
   requires a tag on every misconception, either add the requested tags or relax to "tag, when present, is
   catalogued".
5. `sheets.js` `numbering()` returns "17" for voc/def/fact/cls/not (the app's own numbering); T06d chose to
   store the teacher's number as `card.num` on asn cards — the Binder can use `card.num ?? numbering(id)`.
