## Wiring added outside my files (BUILD-POLICY §2, one block, marked `// T11`)

`site/js/screens/index.js`:

```js
import { mountBinder } from './binder.js';       // T11
import { mountStats } from './stats.js';         // T11
import { bus } from '../app.js';                 // T11 (live binding — read inside the microtask below)
import { getState, update } from '../store.js';  // T11
import { install as installTrophies } from '../trophies.js';   // T11
…
screens['/binder'] = mountBinder;                // T11
screens['/stats'] = mountStats;                  // T11
queueMicrotask(() => { try { installTrophies({ bus, getState, update }); } catch (e) { … } });
```

The `queueMicrotask` is load-bearing: `screens/index.js` is imported **from app.js's own module body**, so
`bus` is still in its TDZ at that point. One microtask later app.js has finished evaluating. This is why
`js/trophies.js` takes its shell by injection instead of importing app.js — it keeps the module pure,
importable under Node, and out of the import cycle.

### `site/js/trophies.js`

```js
// evaluation (pure)
makeCtx(save): Ctx                               // the read-only view every predicate sees
check(save): string[]                            // ids satisfied right now; writes nothing
evaluate(save, {now?}): string[]                 // ids NEWLY earned; writes save.trophies[id] = {at}
summary(save): {id,name,cond,group,earned,at,progress}[]
progressOf(save, id): {have, need, pct} | null
earnedIds(save): string[]   ·   earnedAt(save, id): number | null

// counters (save.counters — data/trophies.js COUNTERS is the list AND the contract)
bump(save, key, n = 1): number                   // also maintains `<key>Best` for `best: true` counters
setBest(save, key, value): number                // raises the high-water mark, never lowers
resetRun(save, key): void                        // a streak broke: zero the current run, keep the best
counterValue(save, key): number                  // what a predicate sees

// coverage (shared with Readiness C)
coverage(save): {cleared, total, frac}           // === js/readiness.js coverageCount — the Binder fill %
clearedOriginals(save): string[]
rarityHistogram(save, {families = true}): {none, bronze, silver, gold, platinum}

// run accessors (one reading of a run record for predicates AND #/stats)
kindOf(run)      'boss:B4' → 'boss'
bossOf(run)      'boss:B4' → 'B4'  (or run.id when kind is a bare 'boss')
sheetOfRun(run)  'upgrade:AP-1' → 'AP-1'  (or run.sheet / run.id)
accuracyOf(run)  run.acc → run.scorePct/100 → mean clamped credit over items → null
correctCount(run) · wonRun(run) · flawlessRun(run) · isCleanItem(item) · localHour(ms)

// UI
TOAST_MS = 1500
toast(text, {ms?, sub?, doc?}): HTMLElement | null       // null with no DOM
toastTrophy(id, opts?): HTMLElement | null
install({bus, getState, update, doc?, silent?}): {run(), uninstall()}   // idempotent; throws without the shell
installation(): handle | null
```

`install` listens on **`bus.on('graded')`** and **`bus.on('state')`**, so a screen that forgets to emit
`'graded'` still cannot lose a trophy. It is re-entrancy guarded (its own `update` re-emits `'state'`), and
its **first** pass is silent so importing a save does not fire a wall of toasts.

## Behaviour worth knowing

**Binder.** One tab per `data/sheets.js` sheet, in sheet order, Bonus last and dashed. Tiles carry the
teacher's numbering (`numbering(id)`; family tiles show ◆) and, inside a tab with more than one id prefix,
sit under the packet's own section headings (Terms §0 / Notation / Definitions / Facts / Classify;
Warm-up / Problems; Solve by factoring / Family tiles) — without them `voc-01` and `not-01` would both
print "1".

* **tap** → the original (`#/card/<id>`); a family tile has no original, so it taps into its Infinite set.
* **press-and-hold (450 ms), right-click, `i`, `ContextMenu` or `Alt+Enter`** → the tile sheet: rarity chip,
  stem, the **Foil rule printed verbatim from `rarity.js foilRule(id)`**, Foil progress (`have/need`, and
  for class (b) the Variant/review split), the placed note, the card's last 6 history rows, `Open card` and
  `Infinite · <template label>`. List view adds a `⋯` button so the sheet is reachable without a long press.
* The Foil rule is also the tile's `title` (desktop hover tooltip).
* `data-rarity` tints the tile's foot bar; `data-foil="true"` adds the foil overlay (the one gradient S5
  allows) plus a single 700 ms sheen sweep; `data-placed="true"` is the dashed JUMP outline.
* Cover states from `coverState(save)`: `start` → `half` (≥ 50 % cleared) → `full` (100 %) → `platinum`
  (every original **and** all four family tiles Platinum). The strip next to the fill % counts the 164
  originals only, so its total is the number the fill line prints.
* Tab + view are in the hash (`#/binder?sheet=FAC&view=list`) via `history.replaceState`, which fires no
  `hashchange`, so switching tabs never re-routes; the open tab is scrolled into the strip, never the page.
* `data/cards.js` (≈ 230 KB of stems) and `data/templates.js` are **lazily imported at mount**, so having
  the Binder in the screen registry costs the first paint of `#/today` nothing. The tile sheet renders
  immediately from `rarity.js` and re-renders once the template registry lands.

**Stats.** Ghost target ("120 / 480 XP — beat yesterday: 360 to go"), Readiness sparkline over
`forecastLog` with the live number from `readiness(save)`, 14-day XP bars (goal-met days green, the bar
scale is `max(dailyGoal, best day)`), rarity histogram, the 19 skill bars from T10's own `skillStates`
(untested grey, mastered gold, weak rows get a `Drill 5` link), first-try % per day computed from every
card's attempt-1 history entries, per-sheet / per-Page / per-boss / per-Mock bests, all 60 trophies grouped
and collapsible with a meter on each unearned counter, Patterns via `misconceptions.groupByArea`, and the
error log with `Replay` / `Rematch` deep links (`#/card/<id>` or `#/variant/<tpl>?seed=<seed>`).

Both screens push the header's Readiness ring (`setHeader`) so a deep link into either never shows an
empty ring, and both re-render on `store.subscribe`.

`tests/trophies.test.mjs` holds a `FIXTURES` map keyed by trophy id; the suite asserts (a) every id in

sheet but does not gold it; 19 setups is not 20; a won boss is not a flawless boss; 89 % is not Mock 90; a
prediction 6 points out misses; 22:10 is not "not a night owl"; a page with one non-clean item is not

## Open issues

1. **`qa/shot.mjs --state` does not work** (not my file — reported below). It writes `u1a.save` **after** a
   warm-up page load, and the app's 250 ms debounced write from that load lands afterwards and wins, so
   every `--state` screenshot renders a *fresh* save. I verified this (`--eval` showed `testDate: null`,
   `cards: 0`). I used a scratchpad driver that injects the save with `context.addInitScript` instead
   (`/private/tmp/claude-501/-Users-oliver/a4b3cdf7-f4be-4831-9be9-2af12b15793b/scratchpad/shot2.mjs`) —
   a one-line fix for whoever owns `qa/shot.mjs`.
2. **Nine counters are not bumped by anything yet.** `COUNTERS` names the owner and the exact moment for
   each. Until T09/T12/T13/T16 call `bump`, nine trophies (`both-roots`, `two-cases`, `reject-x5`,
   `setup-artist`, `notation-20`, `sign-master`, `forge-flash`, `systems-10`, `cold-recall`,
   `reasoned-36`) are unreachable in the running app. They are fully specified and tested; they just need
   their call sites. `comeback` needs nothing — it also reads card history.
3. **Run records are thin in the fixture** (`items: []`, no `xp`, no `acc`). Stats prints an honest `—`
   rather than a wrong number, but the per-Page "XP"/"Clean" columns and Mock accuracy stay blank until
   runs carry those fields (see Requests).
4. The `<details>` open/closed state of the trophy groups is kept in a module-level `Set`, so it survives
   a re-render and a remount but not a reload. Deliberate — no extra localStorage key.
5. `install()` is a module singleton (idempotent, `uninstall()` releases it). If a later ticket wants a
   second instance for a sandbox, that needs a small change.
